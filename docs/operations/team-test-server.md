# 线上团队测试服务器准备

本环境供老板和团队查看和体验核心业务，使用独立测试数据库与访问身份。它承接经本地核验的旧数据副本，不连接旧平台在线写库。已选香港 Ubuntu 22.04 ECS（2 核、8 GiB），域名为 `test.nanproduced.cloud`、`admin-test.nanproduced.cloud` 和 `api-test.nanproduced.cloud`；实际服务器、解析和部署状态以操作前核对为准。首次导库与启动平台须经 Owner 本地验收和审核。

## 先准备的资源

| 项目 | 准备内容 |
|---|---|
| 服务器与访问 | 香港 ECS、64 位 Ubuntu 22.04、Workbench CLI 或 SSH；运行 API、Next、静态 Admin、PostgreSQL、Redis 和反向代理的 Compose 服务，核对时间同步与磁盘余量 |
| 容量 | 提供实际CPU/内存/磁盘/带宽配额。构建尽量在CI/独立构建机完成；运行、迁移和压测分别记录峰值，再定容。磁盘须覆盖当前库、源dump、转换中间件、一次可恢复备份与日志余量，不能按压缩dump大小估算数据库空间 |
| 网络 | 同地域VPC内连接PostgreSQL/Redis/OSS，数据库与Redis不开放公网；入口HTTPS，SSH只对维护者IP。API3102与Next3100只绑定本机/私网；Admin静态资源由反代提供 |
| 域名/TLS | 用户、Admin、API三个Origin和对应证书、DNS、续期责任；回调URL预留HTTPS。证书主机名与实际数据库/Redis连接地址匹配 |
| 数据 | 独立 `zzsh_ecs_test*` 目标和独立 owner/migration/runtime；生产切换改 `zzsh_prod*`，不改同一库的身份假装换环境。首版从已核验的完整快照恢复，核对 schema、迁移记录及权限；仅全新初始化时安装 initial 和尾迁移，不对恢复库重复初始化 |
| 对象存储 | 首版使用现有 `zzsh-dev` Bucket，暂不开 CDN；旧账号截图按约定路径映射，尚未上传的图片允许后续补传。数据库备份放独立受限位置 |
| 三方 | 按[配置清单](deployment-prerequisites.md)配置短信、云信 dev、OSS 及银行卡保护钥；首版用户实名二要素关闭，管理员 TOTP 仍启用。真实汇聚调用保持关闭，测试资金操作仅使用明确标识的模拟能力 |
| 恢复与观察 | 数据库自动备份/PITR能力与一次真实恢复验证；日志轮转、磁盘/内存/错误率/延迟告警；备份加密、访问控制、保留周期与恢复负责人 |

PostgreSQL 与 Redis 由 Compose 部署在内部网络，按测试服运行配置校验证书，不对公网发布端口。运行细节见[测试服 Compose 说明](ecs-test-compose.md)。

## 三端部署关系

- 用户域名反代到Next生产进程；用户 `/api/*` 经既有Web BFF转发，Next服务端设置 `ZZSH_API_ORIGIN` / `ZZSH_WEB_ORIGIN`，不向浏览器暴露密钥。
- Admin域名提供 `apps/admin/dist` 静态文件；其 `/api/*` 原路径代理API（`/api/bff/admin`、认证路径保留，不另造业务规则）；SPA路由fallback不能覆盖 `/api` 错误与媒体响应。`vite dev/preview`不是生产服务器。
- API域名承接明确的公开/认证/BFF/供应商回调路径。反代清理客户端伪造内部头，再写真实IP；只信任已知代理。不要给全部来源加CORS，不把数据库或owner工具挂到公网。
- 服务由 Docker Compose 管理，固定 Node 24 基线与 lockfile 构建，保证优雅停机、readiness 摘流和日志脱敏；敏感配置通过受限文件注入，不复制本机 `.env`、TOTP 或 fixture 到服务器。

## 部署顺序与进入体验条件

1. 固定同一版本的代码、initial、测试扩展与数据来源；在本地验证核心链路和必要权限，记录已知问题，由 Owner 先审核。首版测试数据允许按可复核的脚本步骤依次准备，不要求先完成正式切换的一键工具。
2. 备份新目标当前状态并试恢复；确认maintenance/migration/runtime三种身份、真实OID、TLS、schema与权限。安装与数据转换分开留回执，UNKNOWN按原键恢复，不换键重发。
3. 首版可使用已生成的第七轮快照（旧源截至 2026-11-03），在不修改原库的前提下制作独立演示副本，并记录已知缺口；最新旧库 dump 的完整转换后续进行。原迁移范围为付款记录成功的订单及其账号，以及截点在架账号；核对用户、关系、金额、状态、期初、银行卡和初始化结果，不迁旧上架保证金、旧管理员或旧聊天记录。
4. 本地导出并在隔离目标实际恢复，核对数据库权限、密钥版本和数据；Owner 审核通过后再导入 ECS、启动 API→Web/Admin。验证登录、浏览/上架、模拟下单、客服开租与结算，以及模拟退款/提现已实现的范围；模拟事实不能标为真实渠道到账。
5. 测试站保持公网可访问，使用平台自身登录与权限控制；体验页面标清测试环境及数据截止时间、可操作范围和反馈入口。管理员首次使用初始密码登录并自行绑定 TOTP，不带入本机活跃会话或已绑定 TOTP。

迁移每阶段记录开始/结束、行数/字节数、吞吐、批量大小、锁等待、重放/隔离/恢复耗时与峰值资源。区分可提前准备、停写窗口必做和可后补工作。本地冻结副本的耗时用于发现瓶颈；线上停机预算需以最新数据量和目标机器实测确定，不能直接照搬。

回退按应用版本与兼容的前向 schema/数据恢复合同执行；不盲跑 down SQL、不覆盖已接纳资金事实。团队演示可在 Owner 确认数据恢复、访问范围与已知限制后开放；尚未验证的核心流程须明确告知，不能作为正式上线或真实资金验收结论。
