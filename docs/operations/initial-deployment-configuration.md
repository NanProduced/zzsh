# 首次部署初始化配置清单

本文用于核对首次部署需要的账号、业务政策、内容和运行环境。它记录现有实现和已确认要求，**不是已完成的初始化回执**；标为“待接入”或“待确认”的项目不能当作已有默认值。部署的域名、数据、密钥和渠道分别按测试环境、正式环境准备。

当前新装结构基线为 [`release_production_0174`](../../apps/api/migrations/initial/release_production_0174/)，静态数据在其中的 `02-initial_data.sql`；基线之后的迁移以合并后正式 journal 和目标数据库版本账为准。配置来源及密钥文件的具体位置见[部署配置准备](deployment-prerequisites.md)。

## 首次初始化与后续发版

- **首次部署**针对明确登记的空目标，只执行一次结构安装、管理员创建和已确认配置初始化，再独立读回。初始化来源可为版本化默认值或服务器上的受限配置文件，不要求先登录 Boss、在管理平台逐项提交审批。各项入口仍须完成实现和验证。
- **已有环境的常规发版**只按版本账执行必要的增量迁移并更新程序；不得重复执行空库 initial、重新生成账号密码或 TOTP、清空数据库、重置密钥或覆盖运营已保存的配置。新版本确需补一个此前不存在的配置时，应有明确的增量迁移或升级规则，保留已有值并核对结果。
- 管理平台后续修改使用对应业务的权限、校验和版本规则。新配置成为当前生效版本，已有订单的冻结价格、结算和等待期继续按原版本处理，不用当前值倒推或改写历史。
- 首次初始化必须保留配置来源、版本与结果证明，允许安全地核对既有结果；结果不明、目标已有冲突数据或来源缺失时停止，不生成虚假审批、不覆盖现有值。明确的测试环境数据重置是另一项操作，不属于普通发版。

下表中的“已有”表示源码或基线里已有该值/机制，并不代表某个部署环境已经正确初始化；“待接入”表示目标行为尚需开发或整合；“待确认”表示具体经营值或正文仍需核对。

## 管理员与基础权限

| 项目 | 首次部署要求 / 默认值 | 当前状态与核对重点 |
|---|---|---|
| Boss 账号 | 固定两个：`ZZ00001`、`ZZ00002`；分别设置初始密码。本人首次登录后改密、绑定 TOTP 并激活；首次激活不设 15 分钟截止。 | 本地受控创建和独立只读核对入口已接线；合成空库已验证结构安装后的创建、并发及读回，**完整新装、首次登录及交付仍待验证**。旧本地工具会代为激活，不得用于新目标；已激活账号的恢复期限与首次激活分开。 |
| 运营账号 | 初始创建两个普通运营账号，范围为所有游戏，分别设置初始密码；首次激活不设截止时间，由本人改密、绑定 TOTP 并激活；不初始化客服账号。 | 本地受控入口生成各自初始密码并绑定目标；合成空库已验证创建及权限读回，**完整新装、首次登录及初始密码交付仍待验证**。普通管理员创建入口仍依赖已激活管理员。 |
| 角色和权限 | 保留运营、客服预设及权限目录；两个初始运营账号绑定运营预设。 | **已有基础种子，待核尾迁移**。Boss 是独立身份而非普通角色；包赔赔偿最终仅 Boss 审批，须核对最终迁移后的有效权限。 |
| 初始凭据与账号恢复 | 初始密码从环境专用的受限输入产生或读取，各账号独立；不存入 SQL、仓库、日志或公开回执。 | 本地入口将四份初始密码保存于独立受限文件，提交结果不明时按原文件和请求只读核对；完整交付与服务器适配待验。不得复制已激活管理员、会话或 TOTP；已有环境发版不得重置账号。仅首次初始化的四个账号不设激活截止；后续新建员工和已激活账号恢复沿现有期限处理。 |

## 业务政策与交易规则

| 项目 | 首次值或来源 | 当前状态与核对重点 |
|---|---|---|
| 游戏与服务 | 启用的游戏、租赁服务和游戏基础信息。 | 基线不包含经营游戏数据；从确认的业务配置或数据包初始化，**无须先由 Boss 发布的入口待接入**。 |
| 资源与皮肤目录 | 哈夫币、计费物资及单位；安全箱、段位、分类、武器、皮肤、品质和别名。 | 使用现行目录模型及已核来源；目录、单位、可用状态与图片对象需要一并核验。 |
| 价格与价差 | 普通/自定义/极速比例、日耗调整、哈夫币和各物资的租客价与号主价。 | 需提供明确的生效首版；**具体价格待确认**，旧站来源须先核对，不能把示例值当正式政策。 |
| 租期与上架限制 | 可选日耗、租期计算、地区及账号必填项、上架时段等。 | 首版须与服务端校验、页面和现行游戏规则一致；**配置与承接来源待核对**。 |
| 租客押金与包赔 | 押金推荐参数、上下限、包赔选择、费率及适用条款。包赔费 8% 均由号主承担；正常或提前结算按实际消耗对应的号主扣费前收入计算，人工调整和特殊取消按双方核定的号主扣费前收入计算，提前补差单独计算。 | 押金属于租客订单资金，不能与号主保证金合并。**条款新版本及其价格/规则引用待初始化与验证**；不得沿用仍写租客承担或保留待确认占位的测试条款，不覆盖旧封存正文、历史订单或既有同意记录。其他经营参数待核对。 |
| 信用与号主保证金 | 当前代码常量：初始 100 分、违约 −10 分、恢复 +10 分、门槛 80 分、恢复等待 7 天；保证金基础计算为标准租金与物资金额的 5%，封顶 100 元。 | **已有代码规则，待核对首版政策**；具体资格和已有责任以实际政策及记录为准。保证金渠道能力须单独核对，旧站上架保证金已确认不迁移。 |
| 开租自动确认 | 清单生成后默认等待 **40 分钟**；配置变化只作用于新清单。 | **已有迁移默认值**；须核最终数据库版本及 worker 是否按该值运行。 |
| 正常/提前结算退款等待 | 分别默认 **0 天 / 7 天**；结算时冻结本单到期时间。 | **已有基线默认值**；政策可调整，真实退款仍依渠道和原付款核验。 |
| 开租前取消原因 | 租客和号主分别使用各自的原因选项；“其他”填写说明。 | 原因枚举由服务端定义；核对用户入口、操作记录和退款链路。 |
| 提前结算规则 | 按项目已确认的实际消耗与提前结算公式执行。 | 公式和文案须对照最终订单候选；不能凭当前政策重算旧单冻结价格。 |
| 会员成长门槛 | 近 90 天：普通 0–4999、银卡 5000–9999、金卡 10000–19999、铂金 20000–39999、钻石 40000+；累计 50000 为黑金资格。 | 规则载于[会员成长](../architecture/membership-growth.md)；政策初始化与读回仍须闭合。 |
| 会员折扣与免押 | 下一轮**测试环境**新单：普通不打折、不减押金；银卡 9.8 折、最多减押金 20 元；金卡 9.6 折、最多减 100 元；铂金 9.4 折、钻石 9.2 折，均免押；黑金跟随钻石。 | 测试值已确认沿用第七轮本地测试政策，初始化入口仍待接入；**正式经营值待确认**。不得以空值或 0 冒充政策，也不改变已批准的既有政策和订单快照。 |
| 会员礼遇折扣范围 | 下一轮测试环境暂沿用挚友、尊享均为支付 100%–100% 的范围。 | 这会使测试环境暂时不能配置有价格折扣的礼遇；最终礼遇范围由 Owner 后续确认，不能当作正式经营范围。 |
| 分销等级与比例 | 等级、默认等级、租客/号主直属上级比例、计佣基数与最低计提额。 | 优先核对同一旧站快照与已确认政策；**新目标首版自动初始化待接入**，不能在缺少来源时猜值。 |
| 分销入账等待期 | 结算后按冻结的等待天数入账，等待期应可在管理端配置。 | 旧站及目标首版的具体值须按同源配置核对；更新只影响适用的新订单。 |
| 提现业务规则 | 单笔上下限、手续费、频率及审核/执行规则。 | **正式值待确认**；团队测试曾使用单笔 2–10000 元、手续费 1 元、每日 2 笔，仅为测试值，不自动作为正式政策。 |
| 用户余额与资金责任 | 新用户按正式规则开户；迁入用户的余额期初取经核对的来源余额。 | 余额和历史退款/佣金是业务数据，不能作为固定默认值；旧历史流水仅按既定迁移口径承接。 |
| 新用户头像审核 | 自定义头像默认需要审核；4 个默认头像为预审素材。 | **基线已有审核默认值**；对象存储中的素材需要另行安装和读回。 |
| 账号筛选与排序 | 游戏可用筛选、地区、皮肤与默认排序。 | 需核首版 `listing_filter_config` 和字典；基线建表不等于已配置。 |

## 环境与外部服务

这些项目与业务默认政策分开管理；表格只列配置类别，变量名、模板和必填条件以[部署配置准备](deployment-prerequisites.md)及各服务示例为准。真实密钥不能写入本文或仓库。

| 项目 | 首次部署需要准备 | 后续发版 / 核对重点 |
|---|---|---|
| 运行模式与域名 | 明确测试或正式 profile、用户站/管理站/API HTTPS 域名、反向代理和可信来源。 | 环境不同，不能共享错误的回调或 Cookie 域；配置与实际公网可访问分别验证。 |
| PostgreSQL | 实例与库、TLS、独立 owner / migration / runtime 身份、备份和恢复方式。 | 核实库身份、版本账和有效权限；普通发版不重装基线、不重建库。 |
| Redis | 独立服务、TLS 和应用 ACL；目前以实际代码使用范围为准。 | 不因模板存在就认定业务缓存或持久化已验收。 |
| 认证与应用密钥 | 用户和管理员认证、限流、ALTCHA、订单确认、列表游标等独立密钥和版本。 | 首次安全生成并备份；更新不得随机替换既有密钥。 |
| 实名及银行卡数据保护 | 身份主体摘要、旧实名资料加密、银行卡加密密钥及历史版本。 | 与导入数据匹配并可恢复；不能重新生成密钥后声称原资料仍可读取。 |
| OSS 对象存储与 CDN | 环境专属 Bucket、地域、前缀、上传/CDN 域名和证书、受限运行与回源身份。 | 按[媒体存储与环境准备](media-storage.md)核对直传、水印、公开/私有访问、缓存和撤回；素材和历史图片逐对象核对，静态临时凭据不能当作已实现自动续期。 |
| 用户短信 | 签名、各主动验证码场景模板、变量、密钥与权限。手机验证码为 4 位。 | 测试环境仅发送主动验证码；自动业务提醒上线前另行实现和验证。 |
| 实名二要素 | 已订购服务、接口配置、凭据和调用频率限制。 | 测试及正式环境按各自决策配置；提供凭据不等于完成真实核验验收。 |

| 汇聚支付 | 收款、退款、提现、查询各自的商户配置、密钥、回调与允许的渠道能力。 | 测试模拟和真实通道分开；本地或模拟成功不代表汇聚或银行到账。 |

| 监控、日志与备份 | 各服务健康、告警、日志脱敏、数据库和关键密钥备份、恢复位置。 | 策略、保留期和恢复演练需明确；日志不得包含原始证件、银行卡或密钥。 |

## 已发现的初始化改造项

| 环节 | 当前依赖 | 需要达到的状态 |
|---|---|---|
| 管理员创建 | 旧本地脚本会自动改密、绑定 TOTP，并依赖已激活 Boss 创建普通管理员。 | 首次只创建两个 Boss 和两个全游戏运营账号及其初始密码，四人自行激活；既有环境不重建账号。 |
| 旧数据导入执行身份 | 核心导入和专项脚本仍绑定管理员会话；实名关联、余额期初等环节还要求已激活 Boss。 | 首次部署须支持经限定的系统迁移执行身份及真实审计，不伪造管理员会话；改造和端到端验证完成前不能开始新一轮全量导入。日常管理权限保持原有校验。 |
| 游戏规则、协议和分销政策署名 | 部分版本的创建、封存或生效列要求管理员 ID。默认内容与法律文书初始化可引用已创建但尚未激活的初始 Boss，由迁移身份执行并记录系统审计。 | 不伪造管理员登录或审批；游戏规则和分销政策的初始化入口仍须按最终方案验证。 |
| 会员与分销首版政策 | 旧初始化及轮次读回仍依赖审批申请、决定和执行。 | 使用经确认的首版配置直接初始化，保留来源和生效版本，不制造审批记录；日后运营变更仍走实际适用的业务流程。 |
| 首次初始化验收 | 旧轮次合同要求已激活管理员、TOTP 和旧审批回执。 | 按新合同独立核对四个待激活账号、政策与内容来源、运行权限及最终配置；不能拿旧回执代替新证明。 |
| 后续发版 | 新装 SQL、静态种子和运营配置在工具中仍需明确区分。 | 已有目标只做版本化升级，验证已有账号、密钥和政策未被初始化逻辑重置。 |

## 对照与交付检查

1. 逐项确认经营数值、文书、角色范围及环境差异；未确认项保留待定，不由程序猜测。
2. 确定每项使用代码默认值、initial SQL、服务器受限配置还是旧站经核对的来源；需要持久化的当前政策须有独立读回，不覆盖原快照。
3. 完成不依赖已激活 Boss 的管理员、业务资料、法律文书、会员与分销首版初始化，并核对重复执行和已有数据保护。
4. 对新装与已有库升级分别验证账号、默认配置、权限、中文注释和运行时读取；旧数据迁移另做来源、金额、关联与异常对账。
5. 最终版本合并后重新核迁移顺序、静态种子和文档；测试结果及未运行项单独记录。真实短信、实名、云信和汇聚能力须分别受控验收。
