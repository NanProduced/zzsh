# 业务领域术语

## Language

**皮肤词条**：某个游戏中的具体干员、枪械或近战外观。三角洲近战武器本身作为独立外观词条；名称相同但所属干员或枪械不同，不能视为同一词条。

**皮肤类型**：干员外观、近战外观或枪械外观，与品质、典藏和默认状态分别描述不同事实。

**皮肤品质**：同游戏品质字典中的档位，如传说、史诗；依据分别记录为官方资料或平台参考资料，平台资料不冒充官方已核。旧平台的“红皮”“金皮”分组不作为品质，未知保持null。

**典藏属性**：独立于品质的是否典藏标记，区分是、否和未知；不作为品质排序，也不自动增加价格或推荐押金。

**默认状态**：默认外观、非默认外观或未知，不从名称、图片或典藏属性推断。

**所属对象**：干员外观所属的干员或枪械外观所属的枪械，不是发布出租账号的号主。三角洲近战外观独立存在，不设置刀型父级。
_Avoid_：用“分类”代替所属对象。

**近战外观**：三角洲中可独立选择和申报的近战条目，例如赤枭、坠星者。爪刀、转刀等外形或媒体称呼不构成其所属对象或分类词条。

**显示分类**：帮助用户浏览和筛选词条的分组，不用于证明皮肤身份或决定计费。

**旧业务分组**：旧平台保存皮肤持有信息时使用的分组，仅用于迁移来源对照，不进入新平台的皮肤类型或品质分类。

**别名**：同一已确认皮肤的其他叫法或历史名称；名称相似本身不能证明是别名。

**账号皮肤申报**：号主声明某出租账号拥有的皮肤集合。它不同于平台完整皮肤目录，也不等于官方核验了实际持有。

**皮肤图片**：用于辨认某一皮肤的目录图片，不是号主上传的账号实拍，也不构成该账号拥有此皮肤的证明。

**皮肤词条包**：一个明确范围、可追溯版本的词条及来源映射集合。名称整理、实际导入和配图完成是不同的交付结果。

## 出租账号生命周期

**主动下架**：号主结束一条已发布的出租记录；可确认无付款风险的待付款订单先关闭，付款状态不明或已有已付款订单时须先处理。下架后再次出租须新建记录，不覆盖已产生的订单资料。

**发布资料快照**：订单引用的不可变资料与价格依据；草稿审核过程可以有内部记录，不表示已上架账号可编辑或重新发布。

**出租记录终态**：该出租账号记录已结束，不能以同一条记录再次上架；终态本身不证明旧订单已经结算或保证金已经退款。

## 管理平台授权与运营

**管理员主体**：登录管理平台并执行管理工作的内部账号。用户在订单中的买家、卖家、号主或租客关系不改变管理员主体模型。

**角色**：管理员可承担的岗位能力集合，例如运营、客服、财务、审核/主管和平台安全。一个管理员可以拥有多个角色，最终能力取角色并集。

**数据范围（scope）**：管理员账号可查看和处理的游戏或业务范围。第一版 scope 绑定管理员账号，不绑定角色；角色决定能做什么，账号 scope 决定能看哪些业务对象。

**订单核心信息**：支撑订单定位、客服履约和运营判断的订单信息，包括业务编号、状态、时间、游戏、租赁账号概要、买卖双方关系、订单金额上下文、履约、售后和当前客服上下文。

**上下文读取**：从订单详情查看关联用户、租赁账号或订单资金摘要所需的最小读取能力，不等同于打开对应对象的完整管理目录。

**敏感财务信息**：平台利润、完整资金分录、平台总账和整体收支等不属于日常订单处理所必需的信息，需由财务/Boss能力单独控制。

**技术字段**：UUID、内部对象键、代码枚举和其他实现细节。常规管理页面不直接展示技术字段，应使用业务编号、中文状态和可读标签；必要技术追溯仅在受限审计/技术详情中提供。

## 支付与资金

**四件分开的事实（付款／开租／过账／到账）**：本站接纳付款、正式起租、账务过账与银行到账是四个互不替代的事实，任一成立都不推导其余。订单状态、退款进度与到账状态不能相互解释。
_Avoid_：用「已付款」表示已起租或已到账；用「已完成」表示钱已到号主手里。

**收款请求／付款确认**：收款请求是一次渠道派发的进度，可以结果未知；付款确认是本站对一笔原款的唯一接纳事实。取得支付参数不等于付款，渠道报告成功也不等于本站已接纳。

**经济根**：一笔钱在站内的唯一身份，由渠道、稳定商户身份与渠道流水共同确定。轮换配置或密钥不产生第二笔钱；订单号不是渠道流水。

**资金事件／平衡分录**：不可变事件与其配平分录决定站内账务，页面状态不创造余额。更正走新的关联记录，不追改原分录。

**余额依据／已核期初**：某时点余额只有在期初依据被取得后才能核定；缺依据保持未知，不按零展示。覆盖笔数不代替期初余额证明，账内算术一致也不代替历史承接完整。

**账本修订／读取修订**：账本修订（`ledgerRevision`）是资金写入核对的钱包版本，提现等命令用它拒绝陈旧写入；读取修订（`readRevision`）表示读取侧事实是否变化，用于让列表游标和快照失效。二者都不是余额，也不是可提现额。

**应退责任／退款意图／本地核销／退款到账**：四件分开。责任成立不代表已提交渠道，本地核销不代表银行已出款，已分配的额度不是未到账金额。

**未开租终止**：已付款但未正式起租时，由当事人直接取消并登记全额应退责任的独立处置；服务端核对原付款、未开租、未过账及无待处理调整或分佣冲突。历史遗留申请才需客服核准。它保留原付款事实，不伪造完成、起租或正常过账；登记或核准不等于退款完成。

**号主上架保证金／租客押金**：两笔不同的钱。押金随原订单付款与应退一起核算；保证金是独立的收退业务，两者不互相抵扣，也不自动计入可用余额。

**计佣基数／冻结依据／计提／成熟**：付款时冻结计佣口径与依据，结算过账后按该口径从不可变过账确定基数：平台结算贡献减包赔费用、旧价差口径（实付减号主实结及租客应退）或固定费口径；再计提并到期成熟。订单支付总额、冻结估算和历史观察都不是佣金。

**注册来源／分销上级**：注册时的邀请关系与该笔业务的直属受益上级分别保存，登录不重写注册来源。

**本地受控／合成协议证据／真实渠道结果**：三类可信度不同的记录或证据，不能互相改名，也不能由前者推导后者；合成协议只是离线协议证据，不是款项，真实渠道结果还要区分请求候选与已核验结果。

**可提现额**：钱包按覆盖、预留与追偿核对后给出的申请参考额；有未清追偿时给出 0 并标记阻断原因，覆盖、预留或修订依据不完整时保持未知，不补零。政策、身份、出款目标和渠道资格在报价或申请时另行核定，不等于全局可提现额。

## 会员计价

**基础租赁与资源费**：按账号适用的基础规则计算的哈夫币租金与物品资源费合计，是会员和礼遇折扣共同使用的基数，不含押金、号主保证金或赔偿。

**会员折扣**：由管理平台为成长等级配置、作用于基础租赁与资源费合计的应付比例；具体比例属于经营配置，不由成长积分门槛推导。
_Avoid_：将基础哈夫币价差或物资单价称为会员折扣。

**人工礼遇**：后台为特定用户手动发放、具有明确折扣和有效期的额外权益，独立于自动成长等级；免押是可独立授予的另一项权益。

## 界面用词边界

客服会话统一使用“待接入／接待中／已结束”；消息通道异常与接待阶段分别表达，“暂不可回复”不表示入站消息被禁止。订单“待确认开租”“租用中”“结算已完成”沿服务端阶段；客服手动结束仍可能有待处理资金，不统称结算完成。

三角洲界面使用“安全箱”和“极速出租”，原字段标识、历史别名和冻结记录不因改词重写。会员价格权益称“会员折扣”，精确应付比例作为配置说明；部分押金减免不称免押。物品资源费按阶段可写“物品资源预付款”或“物品实耗费用”，不能与押金、包赔或哈夫币费用合并改名。

测试环境的模拟扣款／出款必须显著说明，不以删去“本地”等字样伪装真实渠道。普通业务页的实现词可换为简明解释，原请求、技术原因和来源证据仍保留在必要的受限详情中。

## 资金与对账

**押金**：租客为一次订单支付、结算后可退的资金。它不是号主保证金，也不计入号主收益。
_Avoid_：用“保证金”指租客押金，或用“免押金”描述号主缴付。

**号主保证金**：号主为出租账号缴付的保证资金，用于覆盖违约与赔偿；与订单押金、信用分分别记录。会员免押不免除号主保证金或包赔责任。
_Avoid_：把“出租账号保证金”“上架保证金”“发布保证金”当作不同对象。

**信用分**：号主的信用评分，只说明信用状态；80 分是当前号主保证金的门槛线，实际应缴金额仍以核定结果为准。信用分不代表可以交易，也不代表无需缴纳保证金。

**站内提现与渠道提现**：站内提现是平台自己记账的出款流程，未接真实渠道，不产生实际打款；渠道提现才提交给支付渠道。两者都不得直接宣称“银行已到账”。
_Avoid_：把“本地受控”作为面向用户或客服的界面用词。

**出款三段**：提现申请、平台出款、银行到账是三个不同事实。已受理不等于已出款，已出款记录不等于银行到账；渠道结果与本站记录不一致时单列“结果冲突，需核对”。

**退款责任与核销**：应退责任可来自正常结算过账、未开租终止或已开租客服特殊取消，需在对应原责任和退款意图上完成终态证据（渠道或本地受控）与本地核销；申请被受理或额度已分配不等于核销。已过账与未核销可以同时成立；“未核销”不等于未结算，也不等于渠道未退款。

**保证金缴纳与退还记录**：责任状态、缴纳尝试状态、退还尝试状态、渠道请求状态分别记录。缴纳款已记录、退还已记录都只说明本站记录，不表示渠道到账。

**未识别状态**：服务端返回值没有登记词表时，界面统一显示“状态暂不识别，请刷新后核对”，不得回显英文码，也不得计入成功或失败。

## 订单、履约与结算

**付款、开租、结算、佣金与到账**：订单已付款、账号已开租、订单结算已完成、分销佣金已结算、退款处理结果、渠道结果、银行卡到账分别描述不同事实；任何一方不得为统一叫法而被写成另一方的“成功”。

**订单终局方式**：未付款取消（用户、超时或客服）、未开租终止、已开租客服特殊取消和正常结算完成是不同处理，条件、资金后果和记录来源都不同；`MANUAL_CLOSE` 仅保留历史记录，不再作为新已付订单的结单方式。
_Avoid_：把这些处理统称“关闭订单”。

**开租确认**：买卖双方对期初清单的确认；客服代确认只代替某一方的确认动作，不改变另一方仍需确认的事实。

**结算完成**：结算已过账到财账，是订单侧事实；它不表示渠道清算、退款完成或任何一方银行到账。

## 客服与会话

**咨询**：用户与平台之间的一次在线咨询往来；投诉是在线咨询的一个类型，不另建工单或独立队列。

**订单群**：付款后为某个订单建立的三方沟通群，与在线咨询是不同对象，但共用消息基础组件。

**会话**：咨询与订单群在列表语境下的总称，只在列表、菜单和搜索中使用。

**接待状态**：待接入（还没有客服负责）、接待中（已有客服负责）、已结束（本轮结束）。动作名与状态名分开，“结束咨询”是动作，“已结束”是状态。

**消息通道异常**：`FAILED` 表示当前客服会话的消息通道不可用、暂不可回复；它不表示入站消息被禁止，也不表示订单或咨询本身失败。队列行必须显式呈现异常，不得显示成普通待办。
_Avoid_：在接待与用户文案中使用渠道内部名（渠道名仅出现在系统配置与安全诊断页）。

## 分销与邀请佣金

**邀请佣金**：号主或租客因邀请关系获得的收益；用户端与后台指同一笔钱。待追回是从已结算佣金中扣回的责任，不改变原记录金额。

**佣金阶段**：待结算（未到结算时点）、已到期待转入余额（到期但尚未过账）、已结算（已过账）。只有确有钱包入账证据才说“已转入余额”。
_Avoid_：用“待入账”同时指待结算和已到期待转入余额。

**计提与转入可用**：分销账本的两个动作；“分销转可用”“已登记追偿”不再作为界面用词。

**历史观察**：旧平台分销记录只作为历史观察呈现，不并入当前钱包，也不因文案改动而变成当前资金事实；用户不需要在新旧平台之间选择数据来源。

## 缺失与受限状态

界面缺数据时必须可区分五种情况：无权读取（“你的账号无权查看该项”）、暂时读取不到（“暂时读取不到，请稍后重试”）、本站没有记录（“本站没有这类记录”）、需要人工核对（“需要人工核对后才能确定”）、等待他人处理（“等待他人处理”）。不得统一写成 0、“暂无”或“稍后重试”，也不得以“待核”一词覆盖多种含义。

展示词表的实现位置：跨端共享的中文标签与单位适配在 `packages/ui/src/display-*.ts`，各端按域入口引用；新增枚举值须同批改词表和覆盖测试。当前共享词表已覆盖号主保证金（责任／缴纳尝试／退还尝试／渠道请求）、分销佣金状态与账本动作、资金义务队列（退款责任／站内提现／渠道提现）、消息通道状态和元↔分换算；其余页面的现场措辞按后续批次迁移，不视为已完成。
