# 分销看板

管理端分销分为概览、佣金明细、分销商、关系查询和政策五个入口；分销商详情为对象页。旧 `/distribution-policy` 及其已保存的佣金、关系分区继续映射到相应新页面。

`distribution.dashboard.read` 独立控制汇总、列表与排行，不授予资金账本、内部计佣基数或资金操作。0148只登记权限，不自动赋予角色。姓名和目录入口另需 `user.directory.read`；订单、凭证链接继续检查原有权限。无游戏维度的完整参与者、邀请关系及邀请榜仅允许Boss或ALL_GAMES范围，选定游戏的佣金先按订单游戏过滤。

管理端按佣金业务统一概览、最近记录与排行，来源只保留明细追溯，不构成两套余额或排行榜。当前状态按已接入佣金记录及已准入当前责任计量，不受期间筛选影响；旧待结算记录缺少当前责任证明时列为待核对。已结算记录小计不是钱包余额、可提现或银行到账。期间入账使用原根关联财务事件，以及冻结原件和唯一1001 IN日志证明的原入账时间，不直接把旧计划到期或更新时间当入账。未确认入账时刻与原始发生日的条数在期间面板说明，不补零。佣金发生额使用真实原始创建日，订单数只统计期间发生且已关联的订单；当前待追回取实际未追回金额。完整来源覆盖仍待核，任务佣金不得按同号租赁单授权或链接。

分销商列表与详情复用同一佣金记录及责任口径，分别列已结算、待结算与待核对记录。旧资格及原档位ID仅在原导入审计与参与者来源摘要一致时显示，不能替代当前政策下的计佣资格；未发布政策时不伪造可计佣状态。关系子集已接入条数与完整子关系总数分开表达，闭包未知不显示为完整零关系。

`GET /api/v1/admin/distribution/{overview,earnings,participants}` 与参与者详情为纯读。读取在一致只读事务内完成，出参前重核当前身份、权限与游戏范围。分页快照绑定身份、会话、有效权限、范围、筛选、数据版本及有效期；版本覆盖受权来源的原位修订，不因无关游戏或其他资金事件变更而失效。翻页缺快照或签名错误返回400，过期或绑定漂移返回409并重新加载第一页。

用户 `GET /api/v1/users/me/distribution/summary` 只返回本人摘要、期间入账、趋势和近期佣金。用户收益记录统一展示迁入与当前记录，沿原日期排序、按当前已知责任状态筛选；来源和适用旧规则放入明细，不要求用户先选择平台代际。未明确的历史责任保持待核，不把旧待结算状态直接冒充当前待发金额；钱包仍只取正式接纳的余额事实，不能与观察小计相加。合法空集合显示0；缺少来源显示未知。金额事实保留整数字符串，图表数值只用于坐标，Tooltip与表格使用原金额精确格式化。不可绘制的数值回退精确表格。

政策编辑、审批、计提与冲回仍遵守[分销与提现合同](distribution-and-withdrawal.md)。看板不启用政策或worker，不补发旧佣金。旧关系审计不是导入，尚未准入的v2历史映射不得显示为已承接。
