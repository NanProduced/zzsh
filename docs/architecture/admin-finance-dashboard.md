# 管理端资金与经营看板

资金与经营看板以订单付款、结算贡献、渠道证据和账内余额分别呈现经营情况。原“财务总览”和“期间核对”不再作为侧栏入口；既有期间核对深链和导出合同保留，资金记录、用户余额和汇聚对账仍是独立页面。

## 统计口径

- 订单实付按付款时间归组，每个新订单只取其已接纳的原款，旧订单按源订单付款状态和金额读取；历史来源覆盖不完整时按已接入事实展示，不以空白日期推断零，也不把旧站状态当作汇聚到账。
- 订单毛贡献按结算时间归组：结算基数减租客应退和号主结算净额。新平台使用不可变结算 posting；旧站已完成订单使用原始付款、退款、号主收益和包赔费用字段，金额缺失或不一致时不计算；迁入后续办的旧单仅在确认版本与封签依据相符时计入，缺失或不匹配的记录不计入，不能声称续办数据完整。客服取消订单的资金分配不属于此结算口径，须在对应订单查看；分销、赔偿和渠道成本不包含在毛贡献内，不能称为净利润。
- 付款订单预计基础价差按付款时间归组，排除已取消订单。新订单取冻结报价的全量资源价差，并校验租客资源价减号主资源价等于该值；旧订单取源快照中的 `commission_money`，后者可能已随旧站结算更新。已完成旧单若其记录价差与实付减号主收益及租客退款的旧站明细公式不一致，单列差异笔数并标明未核；仅展示有依据的部分及覆盖数。该口径未扣分销，也未加预计包赔费用；旧站工作台的预计总利润还使用分销和账号包赔等来源，字段承接与覆盖未完整核实时不可称为旧站同值或按零补齐。读取预计价差还需要 `supply.quote.internal.read`。
- 客户排行按租客身份跨来源汇总已结算订单，可按结算或付款时间选择 Top 20/50。排行不将未结算报价当收益。旧站赔偿金额仅为来源记载，不能解释为渠道出款；分销佣金尚未按客户归集，展示待核。
- 页面中的用户可用余额、退款责任净额及提现预留净额均是本站已过账分录的对应科目合计，不是实时汇聚查询。旧历史流水不回放进新账，账内零值不证明旧平台事项已结清。平台分录不是完整平台权益或可提现现金。
- 汇聚商户余额只显示当前管理员获明确商户范围授权后保存的真实渠道快照，不自动调用渠道，不把多个账户简单合计。收款、退款和提现图仅汇总授权范围内已验证并保存的渠道事实；订单来源筛选作用于收退款，提现与订单无关，始终按全部用户统计。旧单迁入后由新站发起且具有渠道成功依据的退款按旧单来源计入，旧平台历史退款观察和模拟退款不计入。提现以本站证据记录时间和出款净额计，渠道成功不等于银行到账。
- 余额来源截点仅作迁移时间参考，不证明订单来源覆盖完整。经营观察中的订单状态分布和租客下单次数分布共用已付订单范围；每个租客按期间订单数分桶，6 单及以上合并。它们仅基于已读取事实，不能直接解释成完整取消率或复购率。

## 读取与权限

`GET /api/v1/admin/finance/dashboard/trend`、`customers`、`channels` 接受 `range=today|7d|30d|all|custom`，自定义范围按北京时间的 `from`/`to` 日期传入，最长 367 天；客户排行接受 `basis=settled|paid` 和 `limit=20|50`，订单分析接受 `source=all|new|legacy`。默认近 7 天、按结算时间、Top 20。所有金额以整数分返回；日和月为显示聚合粒度。

读取要求有效管理员与 `finance.read`；订单聚合还要求订单读取及游戏范围，客户排行另要求用户目录读取。渠道汇总与商户快照还使用逐管理员明确授予的商户范围。读事务为只读快照，返回前重新校验权限；缺少权限、数据来源或渠道证据时保持不可用，不填补业务数据。

付款订单和状态分布可携带付款时间、来源与状态进入订单列表。结算贡献明细使用 `GET /api/v1/admin/finance/dashboard/contributions`，与趋势和客户排行共用结算事实与公式，支持 `basis`、范围、来源、`asOf`、分页及可选租客；指定租客时另需用户目录权限。明细每笔列出实付基数、号主结算收益、租客应退和毛贡献，并可打开订单。按原范围和事件时间重新读取并不冻结数据库快照，后续补录或状态变化可能造成差异。渠道提交尝试不能充当已确认渠道金额的逐笔证据。
