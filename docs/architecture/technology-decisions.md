# 技术栈确认记录

日期：2026-09-08。工程已完成框架初始化，尚未通过生产验收。

初始化进展：Owner 授权各服务框架搭建后，本轮采用 Next.js 16.3.4 / React 19.2.8 用户站、Vite 8.2.2 / React 19.2.8 自建管理站、NestJS 11.2.3 API、TypeScript 5.9.3、Tailwind CSS 4.3.3，以及共享样式 workspace。Node.js 基线为24.20.0。下方此前“推荐/未冻结”状态中的上述框架已在工程中落地；不代表生产部署和业务验收通过。其他未定项继续保留，具体开发命令见 docs/development.md。

## Owner 已确认

| 项目 | 决定 |
|---|---|
| 业务后端 | NestJS + TypeScript |
| 后端组织 | 模块化单体，按业务领域划分模块；统一业务 API 服务用户站、管理平台及未来多终端 |
| 主数据库 | 托管 PostgreSQL |
| 数据模型 | 核心业务以关系模型为主，JSONB 承载有类型校验和版本管理的受控扩展属性 |
| 多端目标与适配 | Web优先，后续iOS、Android和微信小程序；各端通过服务端BFF适配到统一业务层，详见[多端约束](multi-client-bff.md) |
| 本地运行 | PostgreSQL、Redis 使用 Compose；Node 用户站、管理站和 API 直接在主机运行 |
| 客服履约 | 首期继续使用网易云信，由真人客服处理；新订单每单独立群，支付与履约状态分开 |
| 生产切换 | 开发与测试分阶段推进，正式切换后由新平台单线接管；旧平台不得与新平台共同写订单或资金 |
| 恢复目标 | 资金、订单、审批和审计数据 RPO 不超过 5 分钟，核心服务 RTO 不超过 1 小时；上线前必须完成隔离恢复与对账演练 |

本轮项目初始化采用 npm workspaces monorepo，详见 [仓库结构](repository-layout.md)。用户站与管理站按 Owner 授权已采用下表框架；未落地的组件保持待定。

NestJS 的确认依据为隔离验证与主 Agent 代码复核。验证工程不直接作为生产代码基线；任务租约所有权、重试上限、关单条件及关单后支付等问题需要在正式实现中验证。
