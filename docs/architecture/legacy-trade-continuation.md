# 旧账号历史记录与旧单续办接口

期初余额、历史观察、渠道原号与退款/佣金责任的承接边界见[支付与资金领域规格](payments-and-funds.md#7-新旧资金承接矩阵)；本页维护旧单命令与责任续办。

本合同仅作用于实际纳入[迁移范围](legacy-data-mapping.md#已确认的旧数据迁移范围)的旧订单：以旧租赁付款记录标记成功作为选单条件，已付后取消和仍在履约的订单均保留；找不到成功付款记录时排除，并保留冲突统计。下文是服务能力与业务约束，不代表真实渠道验收已完成。

续办读取、试算及命令/原键回执在服务端按实际当事人裁剪：号主只见本方收入与费用，租客只见本方付款、消耗及应退；双方都不直出平台佣金池。管理端继续核订单/游戏范围与佣金明细权限。原始事实、计算、摘要与幂等存储保持完整，普通重放、并发赢家和只读恢复在发送前执行同一投影，不能借旧回执绕过私价边界。

旧三角洲账号只保留历史资料、来源和订单关联，不接新单，也不在原账号重新上架；号主再次出租须重新填写表单创建新账号记录。迁入时账号的数量、比例和包赔选择只代表采集时的资料，不冒充旧订单的下单快照。其他游戏按已确认的来源与业务范围分别处理。

旧订单保留原租客价格；原号主比例、物资单价或数量不足时，由客服与双方核实并记录，无法核实则交人工处理。新平台账号使用其上架时确认并冻结的规则；不得以新账号现价、新固定手续费或旧站普通客价格替代旧单原价。旧订单保险数量保留原字段的天数语义，不换算成卡片张数。

旧订单不替换为新订单，不因续办重新收款或自动建群；旧群不迁移。受权客服可在管理端为旧单主动创建当前客服和双方的新群，权限与实际云信验收见[客服接入](customer-support.md)。业务命令只新增不可变版本和完整派生事实。迁入时已有、尚待对方确认的旧结算方案保留供追溯，须使用已核实的本单旧价及适用的续办规则重新计算，再由双方确认；不能直接按旧方案过账。

| 路径（相对 `/api/v1/orders`；管理端相对 `/api/v1/admin/orders`） | 方法和用途 |
| --- | --- |
| `/legacy/:mappedOrderId/continuation` | GET 当前有效完整事实、权限、责任及服务端命令指纹 |
| `/legacy/:mappedOrderId/continuation/verify-basis` | POST 受权客服核实并记录双方确认的原始数量、原价和包赔情况；不结算或退款 |
| `/legacy/:mappedOrderId/continuation/preview` | POST 数量预估；当事人或受权客服可用，无资金或状态写入 |
| `/legacy/:mappedOrderId/continuation/propose` | POST 当事人提议；受权客服可选定原租客或号主发起口径并说明原因 |
| `/legacy/:mappedOrderId/continuation/confirm`、`reject` | POST 对方确认或驳回；受权客服核对后亦可说明原因确认或退回 |
| `/legacy/:mappedOrderId/continuation/hold`、`release`、`confiscate` | POST 仅受权管理身份的押金处置 |
| `/legacy/:mappedOrderId/continuation/duties/:dutyId/mature`、`void` | POST 仅受权管理身份的佣金成熟或已核来源作废 |
| `/legacy/:mappedOrderId/continuation/duties/:dutyId/owner-credit` | POST 受权客服核对后将旧在途单号主收益记入平台可用余额 |
| `/legacy/:mappedOrderId/continuation/duties/:dutyId/commission-credit` | POST 受权人员核对后将已成熟的旧分销佣金记入收益人可用余额 |
| `/legacy/:mappedOrderId/continuation/receipt?command=…&key=…` | GET 原请求回执；责任命令额外带 dutyId |

Web BFF沿 `/api/orders/legacy/…`，管理 BFF沿 `/api/bff/admin/orders/legacy/…`。管理BFF必须精确放行上述管理命令，不扩大原生订单写范围。所有写命令保留 Idempotency-Key、原 actor/body 指纹；原成功回执仍复核当前身份、会话、冻结、权限、对象和游戏范围，仅跳过已完成的业务前置。400/409业务拒绝在回滚本次所有命令副作用后保留原键拒绝回执；数据库/通信异常不能伪装为已拒绝。

普通命令体为 `expectedRevision`（首条可null）、`inputEvidenceId`、`planFingerprint`；propose 另带完整八项 quantities，提前结算须选择 `endReason`。客服预览和提议还须选择 `onBehalf`（`renter` 或 `owner`），写入时提供处理原因；客服确认或退回同样须提供原因。计算口径、客服真实身份、审计和方案版本分别留存，不伪造用户本人操作。客服写入仍须 `order.legacy.continue` 与订单游戏范围，且资金处置状态须可核对。每次输入为当前 head.result，结果继承全部有效事实后合并本次delta。命令/证据/责任/CAS/审计同事务。解除暂扣不清 detain，不增加扣留部分退款；87−5仍为82。完成、财账终定和渠道到账独立，渠道未知保持 UNKNOWN；旧单责任写入不代表已原路退款。

发起新方案前，客服与双方核实原始哈夫币数量、号主比例、相关号主物资单价及包赔选择并留痕；迁入时账号资料仅供参考，不能当作原订单冻结值。该核实绑定订单、来源及当前版本，不绑定后续填写的实际消耗；原资料需更正时须重新核实。实际消耗非零的物资仍须有原订单租客单价和已核号主单价，缺失时联系人工处理，不以迁移时普通价格冒充旧会员价格。

旧单使用原订单租客价和核实后的号主价；提前与否按哈夫币实际消耗占原数量是否低于 70% 判断，不随发起方改变。提前补足和包赔费按当前结算规则计算，双方确认后由客服复核；不足或无法核实的情况不自动过账。待确认的旧方案若按原错误口径由租客承担包赔费或采用全量预计收入费基，须退回重算并重新确认；已完成的原始记录保持原样。正常结算由双方确认，受权客服仍可在记录原因后按系统方案处理。退款等待期沿现行正常/提前政策冻结；原付款和既往退款无法确认时须人工核对，不能将渠道状态推断成成功。

迁移一次性为客服预设角色补充 `order.legacy.continue`；后续角色调整、个人 DENY 和游戏范围仍按实际授权生效。授权只使客服能够办理旧单续办，不自动证明资金已入账或退款已到账。

号主收益的客服入账同时要求 `order.legacy.continue`、`order.settlement.write` 和游戏范围，并记录实际经办人与原因。服务端复核确认版本、受益人和期初覆盖；不能排除旧收益已入账时拒绝处理。成功只表示号主平台余额增加，不表示已提现或银行卡到账；重试按原责任和账本引用核对。

旧单由用户或受权客服确认时，系统在确认事务中核对旧来源及期初覆盖，符合条件则自动将号主收益记入平台余额；来源待核时保留待核对责任并留痕，由客服处理。客服确认须具备结算权限；用户自动路径只接受当前事务中真实确认人的有效会话，不允许事后冒用确认人发起入账。

旧在途佣金在订单确认时绑定本次确认版本和成熟时间；迁入时已完结的旧单按原佣金与到期证据保留独立来源。分销到期任务启用时，系统按来源、受益人与期初覆盖核对后自动入账；未到期、依据不完整或历史重复情况无法核清时保持待处理。受权人员也可手动核对入账，另要求 `finance.document.read`；任务使用原责任幂等处理，系统执行身份单独留痕。

旧站售方收入、应退和包赔费的存储字段精确到分。新发起的旧单方案若有不足一分的中间结果，按原字段分别四舍五入，再以入账数重算号主净额和价差并检查守恒；无法守恒时不提交。已接受的方案保留原值和指纹，预览只显示两位金额。

责任经济键为 `(order_id,kind,source_record_id)`。在途佣金先PENDING、成熟为空；confirm按原逐条佣金证据重算终金额，时点为同一次服务端confirm时间+7天。新确认的旧单按正常/提前结算读取当前退款等待政策，在确认版本上固定修订和最早处理时间；后续改政策不追溯修改。升级前已确认但没有截止时间的旧版本保持未知，不能按零天处理。最早处理时间不表示渠道受理或到账。已完成父单佣金走独立不可变admission，保留原行canonical/digest、稳定受益映射、终金额、cutoff、原时间单位和UTC微秒；COMPLETED_AT加旧7天，MATURES_AT直接使用，双证据须一致，不要求旧账号分母或新head。

历史完成未退与暂扣均保留经核净额的 PENDING 退款责任。没有新续办版本的历史完单，客服须核对唯一旧付款记录、汇聚原付款的历史已退与等待期，再创建原路退款任务；暂扣还须确认解除原因并留痕，保留原扣留金额，不自动追加退款。旧记录未保存正常或提前结算标志时，等待期由客服按旧站依据核实，不伪造到期时间。旧侧已没收保留 LEGACY_RECORDS 终态及空新财账 ref，不再次支付；既有退款记录仅供追溯，不等于渠道到账。来源缺失或冲突保留待核，不能以 0 代替未知。

客服特殊取消迁入时仍在履约的旧单时，按原实付约束退款与号主扣费前收入，取消单不产生分销佣金。旧单原记录选择全额包赔时，按号主扣费前收入的 8% 四舍五入到分，从号主收益中扣除；续办记录保存毛收入、包赔费、净收入和平台分配额，既有历史取消记录保持原样。原单是否包赔无法核实时，非零号主收入须先核对；全额退给租客仍可办理。客服在最终确认时核对原付款没有其他已退或未决退款；原单来源闭合且退款渠道已装配时，取消事务同时尝试创建普通原路退款任务，创建失败不撤销取消。历史退款冲突、渠道资料不足或任务创建失败时保留待处理，由客服核对并协调，不推断未退款或重复出款。取消本身不等于退款完成，执行与到账仍以渠道回执为准。迁入的三角洲账号只保留历史；无论旧单如何结束，再次出租均须由号主重新填写表单创建新记录。

对于迁入时仍在履约的订单，旧支付的历史退款金额无法从迁移数据确认时，客服核对原汇聚支付单并留下依据，再由新平台按原付款发起退款。核对需区分原付款此前全部已退金额，以及其中已冲抵本次结算责任的金额；新发退款不得超过本次责任剩余或原支付剩余可退额度。退款等待期、处理中的旧退款、原商户/原支付单和重复请求必须单独核对；人工核对不等于系统取得了渠道回执。真实渠道执行须完成商户与协议装配并独立验证。

共同占用读取新订单、旧订单有效阶段与隔离登记。OCCUPIED优先，其次UNKNOWN，再FREE；缺schema/查询异常不可回退FREE。本人账号列表仅在唯一在途单与当前号主均已绑定时显示旧原单号和跳转；占用事实可成立而无可见订单。供给/新建单与维护导入遵循用户→game→account前缀；续办与财务使用同一稳定mapped order advisory→head→按id排序duty。纯续办仅保持占用或释放，不复开终态；财务先锁全部资金受益人并在共同锁后复核集合，不能持head后补锁user/account。

财务通过 `readLegacyDutyBasis` 重核原命令的完整input/result、逐条终金额与当前有效事实，不把pool、旧stored或派生摘要冒充原佣金行。默认财务hook拒绝，缺resolver保持UNKNOWN。安装严格F适配后，非零只引用最终受益正向ledger；真实终0只可引用专用最终event且无ledger行。四态为NONE、POSTED_POSITIVE_REFUND、FINALIZED_ZERO、UNKNOWN；仅正净退款终定阻断重复处置，零额不清其他责任。

部署必须先装配新的证据/版本/duty/208admission/隔离登记与约束及ACL，再装配读写路由；旧0000–0073不可改。208admission对普通runtime仅SELECT，维护主体才可INSERT，禁止UPDATE/DELETE；actor marker不是审批证明。真实资源迁移、导入、金融终定及渠道执行需要各自准确窗口。本接口的离线实现或组件测试不代表数据库锁、真实数据或渠道验收。
