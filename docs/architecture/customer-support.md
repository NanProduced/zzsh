# 站内客服接入边界

用户端通过全站共享客服容器进入在线客服或投诉咨询；管理员通过客服工作台处理受权队列。咨询与支付后的订单履约群是不同业务对象。订单群已有受控后端建群闭环；三端聊天入口和完整履约流程尚未接入。

订单付款接纳具备隔离受控入口：成功事实、PAID与按服务端App绑定的唯一WAITING记录同事务提交，不开放普通HTTP付款成功入口。本地派单可将WAITING转为ASSIGNED并记录负责人、时刻和审计；ASSIGNED与群READY分别表达，也不开始租用或首响计时。买卖双方IM身份尚未就绪不影响本地付款/分配事实。

## 订单群可靠创建

- 每单保留唯一群记录及CREATE意图，SYSTEM support-manager为群主，买家、号主、已分配客服为普通成员；按App复用稳定身份映射。群名由游戏名和订单编号生成并保存快照，超限明确待处理，不截断订单号。
- 先持久化计划与发送标记，再在事务外请求云信。合法候选Team ID先保存，精确读回归属、类型、名称、成员额度、控制配置及全部成员后，READY、JOINED、操作成功和审计同事务提交。建群失败不撤销付款、释放占用或重复推进派单轮转。
- 响应丢失、已发送后租约失效和写回未知禁止再次CREATE。有候选ID时只核验原操作绑定的同一群；无ID或不匹配时保留NEEDS_REVIEW。只读收敛是服务能力，无任意改群/重建HTTP入口。咨询与订单附着群时共用App+Team绑定锁并互查，避免跨业务重复绑定。
- 订单与咨询共用窄租约/远端互斥助手：持锁连接承担续租和候选回写，短事务期间不插入定时续租；网络等待不持App事务闸门。租约与本地锁不能对已发往云信的请求提供fencing。
- `AuthRuntimeOptions.orderTeams`显式配置成员额度、周期与批次，依赖现有provider和身份生命周期；缺省关闭，不自动注入假成功。已分配订单扫描补漏，派单提交后唤醒，Nest关闭等待在途后才关池。业务无接单容量上限，供应商真实App额度仍需单独核验。
- 扫描的过期处理、首次建群和候选只读核验各有独立的有界循环窗口；单项锁忙或对象状态冲突记录安全分类并继续，回绕后重试，首窗口全锁也不阻断窗口外订单。游标按连接池/App保存在内存，重启从头开始；数据库/连接池全局故障终止本轮，已发送CREATE的未知结果始终不得重建。
- `GET /api/v1/orders/:id/im?operation=read|send`及对应Admin订单接口返回最小状态与成员投影，用户Web经`/api/orders/:id/im`薄转发。买家/号主按当前会话与订单归属；客服按当前会话、游戏范围、同单JOINED及im.support.read授权，发送另需accept。所有JOINED客服平权，负责人不是排他授权；普通订单DTO不返回Team ID，群外管理员不能凭order.read访问。

群READY仅表示本包受控核验通过，不表示人工回应、交付、计时或真实App已验收。首次回应、2/4分钟提醒补派、媒体、72小时只读和安全冻结联动仍待后续实现；订单归档不沿用咨询解散语义。

## 本地派单

- 客服需ACTIVE、未停用、同App的READY身份映射、手动AVAILABLE、CONNECTED且2分钟内心跳新鲜，当前有im.support.read/accept；订单另按游戏范围，Boss按既有范围规则豁免。无capacity列或负载门槛，active_load只保留既有咨询负载统计。
- 订单/咨询分别按last_order_assigned_at、last_consultation_assigned_at最早优先，NULL先、管理员ID打平；成功分配同事务更新时间，presence连接version不变。投诉另需complaint权限，创建时记录用户当前服务咨询及受权关联对象的接待人排除集，claim/transfer沿用。
- 付款发布、订单分配及咨询分配使用同App事务闸门；可派订单按付款接纳时间/订单ID先处理。单批未处理完时咨询保持等待，手动接入/转交提示重试；已先完成的咨询不追溯转走。没有合格订单客服的项保留WAITING/NO_ELIGIBLE_STAFF，不堵住其他可派业务。
- 派单及咨询关闭/转交恢复在对象锁前有序锁定资格与presence；资格行/角色/范围锁忙使整轮延期，不跳到另一客服。供应商调用不占App事务闸门；未知结果仍按原租约/CAS隔离。
- 本地调度仅通过AuthRuntimeOptions.supportDispatch显式传入appId/batchLimit/intervalMs开启，缺省关闭，无环境变量兜底。启动扫描、presence提交后唤醒与周期扫描共用有界消费者，防重叠，Nest关闭时先等在途再关池。主环境不会因合入自动启动。
- 无Team的本地关闭仅将咨询置CLOSED，保留PENDING/FAILED的未建群事实，不虚报REVOKED；所有消息授权仍要求咨询ACTIVE。已建Team关闭沿原供应商核验流程。

## 身份与授权

- USER、ADMIN、SYSTEM身份按应用隔离，平台主体稳定映射到云信账号；PENDING意图与业务创建同事务，外部建号在事务外进行。外部失败不能丢失管理员创建结果。
- Token从已认证平台主体派生，只向READY身份签发短效动态凭据，不接受客户端指定发送身份。SYSTEM群主管理身份不给前端发凭据。
- 咨询按独立Team划分消息范围；服务端SYSTEM为群主，用户和接待客服仅为成员。配置限制不代替真实供应商权限验收。
- 正式客户端发送、读取历史前通过同源`message-access`接口复核授权，拒绝时不调用SDK；授权等待结束后再次检查客户端代次。消息发送复核当前咨询归属、ACTIVE/READY及当前类型接待权限；结束咨询也要求当前指派和当前类型权限。历史读取与继续接待/发送分别授权，已指派不等于永久拥有发送权。
- 平台Cookie失效和管理员PIN锁屏分别以401/423触发身份重确认与本地客户端清理；403按当前咨询阻断操作，不退出账号。客服可在原页面重新确认服务端授权后解除该咨询的阻断；网络错误、旧身份或旧咨询的迟到响应不能解禁。已有云信在线连接的远端撤销仍需另行接入验证，客户端前置检查不能防止持有旧凭据的修改版客户端直连供应商。

## 主要入口

- 用户Web同源代理：`/api/im/token`、`/api/im/consultations`；平台核心路径为`/api/v1/im/user/*`。
- 管理端BFF：`/api/bff/admin/im/*`，使用管理员会话及操作权限；身份目录只提供当前管理员本人映射。
- 本地测试消息代理`/messages`仅在显式注入测试transport时工作，前端按服务端下发的transport选择替身；它不表示正式云信消息通过平台转发。

## 未知结果与生命周期

CREATE/TRANSFER/CLOSE操作持久化尝试、租约与结果。HTTP超时、传输失败、DB回写不确定或过期RUNNING不能证明远端动作停止，进入人工核验并阻止自动重建/冲突操作/无条件重试；纯当前尝试的IDENTITY_PENDING可安全退避。

本地advisory lock只提供进程间互斥，不是供应商fencing。未知结果下暂停UI发送不等于已撤销远端成员权限。安全解除核验状态仍需供应商结果依据。

正常关闭先核Team归属，再解散并精确回读；V2查询只有HTTP200且业务码108404才证明Team不存在，109404（成员不存在）、通用414及网络错误不能作为终态依据。已记录Team的有限CLOSE人工对账绑定原操作、咨询、Team、版本及租约，仅做一次只读确认；确认不存在后同事务完成终态、事件、审计与一次负载释放，不再次解散，不开放通用未知结果自动重试。

客服presence为账号级状态，`version`用于连接/可用状态条件更新；接单、结束及转交只改变`active_load`，不推进连接版本。客户端提交当前版本，过期写返回409，不自动取新版本重放旧离线状态。服务停止不代表presence立即离线，接待资格仍受最近连接时间限制。

客户端按身份/咨询代次隔离迟到响应、历史和实时消息及草稿；关闭窗口不重复创建客户端。已结束咨询可显式进入“再次咨询”并选择类型，提交沿用既有创建/恢复入口；窗口重开、刷新和类型选择不自动建立新咨询。后台恢复与订单清扫均在连接池结束前停止调度并等待在途工作。

管理端复用`/session`刷新权限，独立于SDK是否就绪；客服页因read撤销而关闭后，工作区仍保留恢复发现。并发刷新合并，认证变更期间延后确认；跨标签锁定/解锁及401/423推进失效代次，旧响应不可回写，排队的追尾确认同样遵守认证变更窗口。轮询间隔约5秒，不承诺后台休眠或网络异常时的发现时限，也不代表远端撤权完成。

read客户端身份与send能力分离：只撤接待权限时保留合法连接、历史和草稿，撤read或会话失效时清理敏感状态。`im.support.accept`同时是SERVICE和COMPLAINT的前置权限，COMPLAINT另外要求`im.support.complaint`。发送结果按当前身份/咨询/能力隔离，加载状态由请求所有权收尾，旧请求不能清掉新操作的加载状态。

## 配置与验收范围

`YUNXIN_ENABLED`默认false；关闭时不装配真实provider、不签IM凭据。当前配置仅允许在明确的`APP_PROFILE=provider-test`下开启真实云信配置，并要求AppKey和服务端AppSecret；只设置开关不构成真实调用授权。测试provider/消息transport必须显式注入且具有受限test/fake能力，不能作为生产降级数据。

已完成本地共同迁移至0034、平台Cookie/BFF与受控替身联验，以及独立非生产App的动态Token、真实NIM登录、SYSTEM群主咨询Team、双向文字、当前成员参与期间历史与网络重连验证。Server API按V1/V2分别使用官方端点，返回结构和成员归属严格校验。测试中已知创建成功后的人工修复不代表通用未知结果自动恢复能力。

独立非生产App已验证SERVICE咨询正常关闭及一次旧CLOSE只读对账、平台PIN/会话失效与SERVICE发送权限拒绝；本地测试覆盖客户端清理、迟到响应隔离、presence竞争、再次咨询入口和当前页授权恢复。订单群CREATE、原群只读收敛和对象权限仅以受控provider及隔离PG验证。真实同页权限热恢复完整链路、COMPLAINT独立Team、订单群真实收发、远端在线撤权和进程中断后供应商对账仍须单独验收；回调、媒体/语音、商品卡和完整转交协作未完成。默认关闭，代码合入不启用主环境、不运行主库迁移，也不表示生产客服上线。
