# 站内客服接入边界

## 当前源码与迁移接纳

IM功能正式追加为0125–0141；0000–0124历史字节不改。带旧私有迁移历史的预览库须逐对象/账本核对后另行前向承接，不能只改tag或重复全量执行；源码收录不表示已完成真实PG、部署或云信验收。

客服取消沿用未正式开租的原款全额应退合同；已开租订单使用既有结算/退款流程，不以客服操作绕过实耗、结算或分销责任。新已付单的 `manual-close` 返回409及 `resolution`，按真实开租事实引导客服取消/原款责任或实际消耗结算，不再仅改为CANCELLED而留下不可处理的款项。原 `MANUAL_CLOSE` 状态和成功回执不回写，列为资金待核；Admin订单列表支持 `fundsResolution=MANUAL_CLOSE`，沿原订单权限和游戏范围分页读取。最小售后记录不自行创建新退款能力；应退、本地核销、渠道结果及银行到账分别展示。

平台用户/管理员头像在聊天成员、消息作者和咨询上下文复用严格托管路径，旧外链不恢复；这不表示云信侧资料icon已更新。用户订单引用卡由受权目录或详情返回的viewerParty导航，不信任消息文本中的身份、金额或状态。

旧管理员账号、旧云信聊天和旧订单群不迁入。迁入旧订单的用户可走新平台普通客服咨询，客服按订单、游戏和资金等既有权限查看必要信息并处理。迁移时不自动建群；受权客服可在管理端为旧订单主动发起新群，加入当前客服、租客和号主，旧聊天不会恢复。同一订单只建立一个新群，结果未知时保留待核状态，不重复发送建群请求。旧单在建群前已完成或取消的，发言时间从新群就绪起算 72 小时；之后完成的旧单从完成起算 72 小时，逾期仍可查看。该能力的真实云信与双方页面仍须验收。

`POST /api/v1/admin/orders/{legacyOrderId}/create-team` 要求 `order.read`、`im.support.read`、`im.support.accept`、订单游戏范围及原请求幂等键；本次操作人是群内客服。需装配当前云信 App 和订单群 worker；提交成功只表示建群意图已保存，群实际就绪以后才能沟通。

## 管理端咨询上下文只读接口

`GET /api/v1/im/admin/consultations/:id/events` 与 `GET /api/v1/im/admin/consultations/:id/context` 经管理 BFF 同路径转发，仅允许 GET。在只读、可重复读事务中重验会话/PIN、最新 `im.support.read` 和 App/咨询归属；范围为本人负责或有接待资格的未分配咨询，不依赖 SDK 在线、不建立云信身份。投诉线程另要求 `im.support.complaint`；CLOSED、跨 App、他人咨询和不存在对象统一404。

- `events` 接受 `limit`（默认20、1–50）和 `cursor`。首屏为最近一页、页内升序，`nextCursor` 指向更早页；游标绑定咨询并保留数据库微秒精度，按 `(created_at,id)` 翻页。非法/重复/未知参数返回400。仅输出 `id/type/occurredAt/actor{kind,displayName}/from/to`，不输出事件原始 details 或云信账号。系统事件显示“系统”，姓名为当前投影而非历史姓名快照，缺失管理员名降级“客服”。
- `context` 不接受查询参数，输出 `consultationId/version/service/user/subject/membership`。用户仅包含本咨询已授权的主体 ID（`publicId`）、展示名和安全 HTTP(S) 头像；不含联系方式、证件或账户金额。无关联引用为 `subject.status=absent`；显式 order/account/listing 前缀优先；旧裸引用只在受控来源唯一命中且通过对象关系/公开可见性后解析，否则 `unresolved`。已关联订单可返回用户在该订单的 `party=RENTER|OWNER`，不按用户全局角色推断。本树会员投影未集成时返回 `membership.status=unavailable`，不能解释为普通会员。
- 用户从旧订单进入普通咨询时使用 `legacy-order:<legacy_order_id>`；创建或恢复前检查当前用户为该旧单租客或号主，且来源未标记删除。轮次已有入口引用不改写，后续订单可由用户明确发送引用卡，原草稿保留。
- `GET /api/v1/im/admin/consultations/:id/legacy-orders/:legacyOrderId` 经管理 BFF 同路径转发，只接受 GET；在只读事务内重验会话、咨询接待权限、App 归属，以及该咨询用户与旧单的当事人关系，仅返回旧单业务号、用户在本单的身份及站内目标，不含金额。消息文本中的订单字段不作为核验依据；打开完整订单和资金仍按独立订单、游戏范围与财务权限检查。接口实现与隔离测试不代表真实云信或部署验收。
- 这些读取不产生业务事件、派单、建群或供应商调用。事件接口不是聊天历史归档或关闭操作结果查询；不能用目录缺席或事件缺席判断原关闭是否完成。实现不代表运行环境已装配或真实 PostgreSQL/Auth/HTTP 已验收。

用户端通过全站共享客服容器进入在线客服或投诉咨询；业务咨询与投诉反馈各自保留一条持久线程，历史分别保留。管理员通过客服工作台处理受权队列，管理端按 `kind=SERVICE|COMPLAINT` 分开筛选；投诉另要求 `im.support.complaint`，默认只授予运营预设角色，可由运营配置给指定客服。迁移 `0181` 为升级前仍负责 `WAITING/ACTIVE` 投诉、且仅依赖客服预设的客服写入对象级 `im_complaint_handover_grant`，只保护具体会话，不扩大未分配投诉或新派单；个人 `DENY` 优先。`0181/0182` 必须在同一 pending 迁移批次和停写窗口执行，迁移预检拒绝两者分批，避免跨批新投诉或转交获得对象授权。投诉读取（含消息、事件、上下文和巡检只读）统一要求该权限。咨询与支付后的订单履约群是不同业务对象。订单群已有受控后端建群闭环及买家/号主/客服文字及图片入口，三方已完成local-fake浏览器联验；独立非生产App的订单群文字/图片与历史恢复已验证，完整履约及生产渠道尚未验收。

订单付款接纳具备隔离受控入口：成功事实、PAID与按服务端App绑定的唯一WAITING记录同事务提交，不开放普通HTTP付款成功入口。本地派单可将WAITING转为ASSIGNED并记录负责人、时刻和审计；ASSIGNED与群READY分别表达，也不开始租用或首响计时。买卖双方IM身份尚未就绪不影响本地付款/分配事实。

咨询 subjectRef 解析先消除来源歧义，再按咨询用户检查对象关系：订单须为买家/号主；账号须为本人或存在相关租单关系，否则必须通过与用户站相同的公开 DETAIL 可见性。listing 版本别名还须匹配实际公开版本；公开 UNKNOWN 状态保持未知，不扩大为可租。

## 欢迎消息、发送成功与历史

- `GET/PUT /api/v1/im/admin/support-settings` 经管理 BFF 转发，配置按 App 隔离。读取要求 `im.support.management.read`，保存还要求 `im.support.configure`；保存使用版本检查、稳定操作 ID 和审计。仅配置在线咨询、投诉入口的纯文本欢迎消息（每项1–1000字），只在新轮次开场发送，不重发历史轮次；未配置时使用默认文案。此设置不调整分销策略或资金规则。
- 真实客户端发送前授权绑定消息 client ID、类型和原轮次；成功后登记最小元数据。服务端通过云信单条查询核验发送者、消息身份、类型和时间，再幂等更新摘要、未读、用户首条消息及人工首响。授权探测、撤回授权、机器人消息和 SDK 失败不计人工首响；首响采用核验后的消息时间。待登记元数据按 App/账号持久化并重试，不缓存正文，也不重发原消息。
- 管理端真实历史统一由 `GET /api/v1/im/admin/messages?mode=member|patrol&conversationId=...&cursor=...` 读取。member 复核当前咨询读取权限；patrol 要求管理读取权限并记录巡视审计，支持咨询和订单群。服务端核对 App、Team 和 SYSTEM 群主标记后读取持久群历史，外部读取后再次授权；客户端不获得 SYSTEM 凭据。旧 history/opening 参数仅作 member 兼容别名，不再合并一个限100条的开场补丁。
- 历史消息可附 `sender{displayName,avatar,role,platformId?,displayUsername?}` 最小投影，角色为 USER/ADMIN/SYSTEM。仅按当前 App 与本页真实发送账号批量查询；platformId 仅来自已关联的平台用户或管理员，SYSTEM 不带资料引用。管理员可附规范的公开 ZZ 账号，不从邮箱或手机号推断。头像限 HTTP(S)，不含联系方式或 SYSTEM 凭据。显示名是当前公开资料，不是历史姓名快照；缺失映射不能以云信账号冒充昵称。列表用户也可有公开 avatar。巡视头像和姓名复用实体预览：用户摘要仍需 `user.directory.read` 及原资料接口授权，撤权即撤去已读摘要；客服复用轻量身份卡，不推断订单关系。
- 自动普通文本请求透传原稳定 `message_client_id`；不能仅凭该字段宣称供应商恰好一次或用户已读。投递未知、远端去重范围与附件有效期仍分别处理。
- `hasMore/nextCursor` 来自原始页，游标绑定 App、查看账号、会话、原消息时间及十进制64位ID，不从过滤后的可见条数推断下一页。历史附件复用客户端 SDK 的安全媒体解析与既有媒体组件。
- 真实撤回先核验本人消息，服务端调用云信并保留结果事实；UNKNOWN 不自动重放，历史读取拒绝恢复待核验内容。确认撤回清除历史正文/附件，并同步相同最新消息的咨询摘要。SDK 确认仅本人删除后登记该查看者的隐藏事实，持久历史按这些事实过滤。供应商删除开关、旧消息缺少隐藏事实及删除结果未知的对账属于独立渠道验收边界，不能由本地过滤推断已删除。

## 订单群可靠创建

- 每单保留唯一群记录及CREATE意图，SYSTEM support-manager为群主，买家、号主、已分配客服为普通成员；按App复用稳定身份映射。群名由游戏名和订单编号生成并保存快照，超限明确待处理，不截断订单号。
- 先持久化计划与发送标记，再在事务外请求云信。合法候选Team ID先保存，精确读回归属、类型、名称、成员额度、控制配置及全部成员后，READY、JOINED、操作成功和审计同事务提交。建群失败不撤销付款、释放占用或重复推进派单轮转。
- 响应丢失、已发送后租约失效和写回未知禁止再次CREATE。有候选ID时只核验原操作绑定的同一群；无ID或不匹配时保留NEEDS_REVIEW。只读收敛是服务能力，无任意改群/重建HTTP入口。咨询与订单附着群时共用App+Team绑定锁并互查，避免跨业务重复绑定。
- 订单与咨询共用窄租约/远端互斥助手：持锁连接承担续租和候选回写，短事务期间不插入定时续租；网络等待不持App事务闸门。租约与本地锁不能对已发往云信的请求提供fencing。
- `AuthRuntimeOptions.orderTeams`显式配置成员额度、周期与批次，依赖现有provider和身份生命周期；缺省关闭，不自动注入假成功。已分配订单扫描补漏，派单提交后唤醒，Nest关闭等待在途后才关池。订单与咨询不再设客服个人接待硬上限，`active_load` 仅用于负载展示；供应商真实App额度仍需单独核验。
- 扫描的过期处理、首次建群和候选只读核验各有独立的有界循环窗口；单项锁忙或对象状态冲突记录安全分类并继续，回绕后重试，首窗口全锁也不阻断窗口外订单。游标按连接池/App保存在内存，重启从头开始；数据库/连接池全局故障终止本轮，已发送CREATE的未知结果始终不得重建。
- `GET /api/v1/orders/:id/im?operation=read|send`及对应Admin订单接口返回最小状态与成员投影，用户Web经`/api/orders/:id/im`薄转发。买家/号主按当前会话与订单归属；客服按当前会话、游戏范围、同单JOINED及im.support.read授权，发送另需accept。所有JOINED客服平权，负责人不是排他授权；普通订单DTO不返回Team ID，群外管理员不能凭order.read访问。

## provider-test订单消息路由绑定

- 只有`APP_PROFILE=provider-test`下显式核准的`approvedOrders`（App与订单）会进入测试路由；不按App全局或通配范围接管普通会话。
- 新单先CREATE并精确读回云信Team、群主和成员，再依据服务端身份映射绑定精确App/订单/Team/conversation路由；通过校验后才提交首次READY及首响/提醒计时。
- 已核准目标未绑定或绑定与当前对象不符时，SDK消息和BOT均失败关闭，不回退默认路由。未纳入测试范围的普通会话保持原有发送合同。
- 进程重启后只从可信持久化CREATE候选和精确云信读回恢复绑定；恢复不重建Team、不重复首次READY，也不重置既有计时。
- 本地代码、fake Provider和隔离PG验收不证明公网回调、控制台环境配置或真实云信联验已通过。

群READY表示供应商群绑定与成员已核验，不表示人工回应、交付或租用计时开始。首响与2/4分钟提醒补派后端已完成本地验收；对应提醒界面、真实供应商提醒/补员、72小时只读和完整安全冻结联动仍待验收。订单归档不沿用咨询解散语义。

## 首次接待提醒与同群补派

- 通过既有订单worker显式启用，且须同App首响入口生效；默认关闭，历史群保持NOT_STARTED。新READY群按数据库时钟设2分钟提醒、4分钟补派，提醒只记录一次；不把付款/ASSIGNED或前端倒计时当READY时间。
- 补派在原Team添加尚未JOINED的合格客服，不重建群、不移除原客服。assigned_admin_id/assigned_at保留首次分配事实，responsible_admin_id仅在运行中ADD精确读回成功后更新。无候选进入EXHAUSTED，归属冲突或未知结果进入待复核；不放宽资格或凭轮次自动判成功。
- CREATE每单终身唯一；ADD_MEMBER/BOT_NOTICE按单与轮次留独立操作和审计。已发送ADD结果未知只读核验原Team，不盲目重发；BOT未知不重发，也不阻下一轮合法ADD。取消且未发送的ADD保留历史，目标恢复资格后可用新轮次重选并复用PLANNED成员绑定。
- 可信客服首响停止后续提醒/补派，只取消未发送操作；已发送的迟到结果保留实际成员/操作事实，不重启补派、不覆盖已停止的负责人。扫描的五阶段使用有界窗口，小批次余数跨轮轮转；Nest关闭等待在途结束后再关池。
- 只读投影复用订单IM授权、JOINED群目录及受权订单摘要，暴露首响、提醒时间、轮次、负责人/协作与需复核标记。负责人不形成新的排他权限；普通客服不能读取未参与群，order.read摘要权限也不等于聊天权限。

结算属于订单领域：正常结算由买卖双方确认同一版本后自动生效，提前结算另需客服复核；客服改单须重新确认，特殊人工金额调整沿既有受审流程。云信的首响、接待提醒、补派、机器人消息和已读不构成任何结算确认、责任认定或资金指令。本包不实现这些交易流程，也不因消息送达自动启动退款、入账或72小时归档。

## 订单阶段卡自定义消息

订单阶段卡（开租确认、结束确认、结算完成）由服务端以 NIM 自定义消息（`message_type=100`）发送，`attachment.raw` 只承载 `{schema:"zzsh.order-card",version:1,kind,orderId,cardId}`。NIM 只负责存储和投递；卡片 UI、按钮动作和权限校验仍由 Web/Admin 客户端及订单接口完成。

- 客户端只解析平台自有的严格形状；未知版本、额外字段、非法 ID 或伪造内容按普通文本/不支持消息处理。
- 卡片金额、双方、开租/结算状态一律来自受权订单读取，不信任消息体。
- 自定义消息带可读文本 preview；旧客户端显示该文本或“暂不支持此消息类型，请到订单详情处理”，不阻断订单详情兜底。
- 发送异常、发送后 `SENT` 落库失败和过期发送租约均保留为 `UNKNOWN`，worker 不自动重发；只有身份未就绪、文本通道缺失等待发前检查结果才退避重试，判定发生在 transport 调用之前，不靠捕获错误码区分。查询与领取 SQL 都只接受失败原因为空或 `IDENTITY_PENDING`/`TEXT_TRANSPORT_UNAVAILABLE` 的 PENDING 卡，其他 PENDING 原因保留待核对；人工重排复用同一安全集合。阶段卡账本记录尝试、跳过、未知和失败原因；客服工作台在统一会话列表、订单群列表和详情明确提示“自动卡发送结果待核对”，要求先在群内核对，确认未发送后再按当前阶段手动发送进度提醒；终态订单只提示核对，不重新开放写操作。
- 真实 App 的 type 100 投递、客户端解析和旧版本表现须在目标环境单独验收；local-fake 的卡片结果不扩大真实验收范围。

客服工作台的常规“异常处理/核对结束方式”入口已移除，保留未开租取消和既有 `MANUAL_CLOSE` 历史只读记录；“发起开租确认”改为阶段进度提醒。`POST /api/v1/admin/orders/:orderId/progress-reminders` 要求本单结算写权限与游戏范围，服务端按真实状态选择待开租、待结算确认或租期中提醒，只提醒未确认/未决定方；同一 `Idempotency-Key` 复用同一提醒记录和云信客户端消息 ID；发送用租约认领，成功后落 `SENT` 并记录服务端消息 ID，迟到失败不能覆盖成功。明确拒绝可同键重试；超时/传输错误记为 `UNKNOWN`，不假设相同客户端 ID 一定去重，前端按账号和订单保存待恢复键，要求先在群内核对，确认未发送后再新建提醒。原键重试前复核当前阶段：阶段或接收方已变化时结束旧请求并返回 `STAGE_CHANGED`，不发送旧阶段文案。提醒发送使用订单状态卡而非固定文本，并登记群预览/未读投影；投影失败不回滚或谎称渠道发送失败。提醒不创建清单、不替人确认、不提交结算或退款。群未就绪、无待办或已过账时返回原因而不发消息。新平台订单的开租清单在付款接纳事务内自动生成，客服不再需要手工录入；仅迁移前没有自动生成结论的历史已付款单保留原有手工入口。

## 订单文字入口

- 买家/号主从个人中心租入/出租订单打开共享客服容器的“我的订单群”；客服工作台提供“我参与的订单群”。Admin的`GET /api/v1/admin/orders/im-groups`按JOINED、当前read权限及游戏范围分页，独立于order.read管理目录；群外Boss不因此获得群访问权。统一会话列表的订单队列按管理员/会话绑定，身份变化立即隐藏旧列表并丢弃旧响应；每页50条，刷新按已加载页链重新读取（最多10页）并替换旧快照，翻页与刷新不混用旧cursor；失败/部分失败保留可重试提示，搜索仅覆盖已加载会话。
- 两个容器复用原NIM连接，订单面板没有另一套登录或连接管理器。订单与咨询的上下文、授权、消息与草稿分别处理；订单发送和历史操作前请求订单IM授权，等待结束再次检查身份、App、订单、Team及客户端代次。收起或切换对象不触发付款、分配或建群。
- 固定摘要只展示订单编号/群名、游戏、账号摘要及平台成员昵称头像/身份；内部accid不作默认昵称，会员/实名暂无受权投影时显示未知。没有电话、密码或验证码摘要。订单阶段卡使用 NIM 自定义消息（type 100）承载最小 `schema/version/kind/orderId/cardId`；客户端只解析平台自有形状，金额/身份/状态仍从受权订单读取。用户分享的“关联订单卡”仍走版本化文本标记，两者不混用。
- 本包提供文字发送、实时合并、锚点历史分页及重连后的历史读取。send-only撤权保留合法历史与草稿；read撤权清除当前敏感状态，401/423交回既有认证刷新。订单授权请求按当前上下文单飞，过期结果不能恢复权限。
- `local-fake`仅为显式测试transport：消息仍先经Cookie/BFF/API对象授权，再进入受控内存传输；它不是云信真实消息验收。独立非生产App的实际验收范围见下方说明；本地替身结果不扩大真实验收范围。

## 订单图片消息

订单面板复用同一NIM客户端，支持单张JPEG/PNG选择、解码预览、发送进度、历史缩略图和原生模态大图；单图上限10MiB。上传/发送前重新核验当前订单权限及身份、App、Team和客户端代次。失败或结果未知保留本地草稿，显式重试复用原messageClientId；刷新不能恢复浏览器File，也不宣称供应商已接受的操作可撤回。

测试图片仅在显式local-fake传输可用，以服务端App+订单+Team作为稳定作用域；每次读取重新核验当前会话与订单成员权限，合法买家/号主/客服可读，非成员拒绝。图片不进入公开供给素材库；消息入口单独执行有界请求体与完整图片解码，普通JSON请求上限不随之扩大。历史中任意blob/data/file/javascript地址不渲染，blob只用于当前本地选图预览。

正式SDK图片适配与本地三方图片/历史/失败恢复已验证。独立非生产App已验证一单一群的三方NIM/NOS图片发送和跨端解码，以及买家冷加载、整页重载、组件重挂载、断网恢复后的消息ID稳定。附件URL有效期、远端撤权及生产传输仍未验收。三年消息历史保存不能推出附件URL三年可访问。

## 本地派单

- 客服需ACTIVE、未停用、同App的READY身份映射、手动AVAILABLE、CONNECTED且2分钟内心跳新鲜，当前有im.support.read/accept；订单另按游戏范围，Boss按既有范围规则豁免。业务不设客服接待硬上限；咨询与订单群均按在线合格客服分配，`active_load` 只作统计，不再以“咨询数 + 负责订单群数”阻断派单。
- 订单/咨询分别按last_order_assigned_at、last_consultation_assigned_at最早优先，NULL先、管理员ID打平；成功分配同事务更新时间，presence连接version不变。投诉是独立持久线程：新轮次复用同一用户投诉线程，需 `im.support.complaint`；历史 SERVICE 线程中的合并期消息不自动拆分。
- 付款发布、订单分配及咨询分配使用同App事务闸门；可派订单按付款接纳时间/订单ID先处理。单批未处理完时咨询保持等待，手动接入/转交提示重试；已先完成的咨询不追溯转走。没有合格订单客服的项保留WAITING/NO_ELIGIBLE_STAFF，不堵住其他可派业务。
- 派单及咨询关闭/转交恢复在对象锁前有序锁定资格与presence；资格行/角色/范围锁忙使整轮延期，不跳到另一客服。供应商调用不占App事务闸门；未知结果仍按原租约/CAS隔离。
- 本地调度仅通过AuthRuntimeOptions.supportDispatch显式传入appId/batchLimit/intervalMs开启，缺省关闭，无环境变量兜底。启动扫描、presence提交后唤醒与周期扫描共用有界消费者，防重叠，Nest关闭时先等在途再关池。主环境不会因合入自动启动。
- 无Team的本地关闭仅将咨询置CLOSED，保留PENDING/FAILED的未建群事实，不虚报REVOKED；所有消息授权仍要求咨询ACTIVE。已建Team关闭沿原供应商核验流程。

## 身份与授权

- USER、ADMIN、SYSTEM身份按应用隔离，平台主体稳定映射到云信账号；PENDING意图与业务创建同事务，外部建号在事务外进行。外部失败不能丢失管理员创建结果。
- Token从已认证平台主体派生，只向READY身份签发短效动态凭据，不接受客户端指定发送身份。SYSTEM群主管理身份不给前端发凭据。
- 咨询按独立Team划分消息范围；服务端SYSTEM为群主，用户和接待客服仅为成员。配置限制不代替真实供应商权限验收。
- 正式客户端发送、读取历史前通过同源`message-access`接口复核授权，拒绝时不调用SDK；授权等待结束后再次检查客户端代次。消息发送复核当前咨询归属、ACTIVE/READY及当前类型接待权限；结束咨询也要求当前指派和当前类型权限。历史读取与继续接待/发送分别授权，已指派不等于永久拥有发送权。
- 平台Cookie失效和管理员PIN锁屏分别以401/423触发身份重确认与本地客户端清理；403按当前咨询阻断操作，不退出账号。客服可在原页面重新确认服务端授权后解除该咨询的阻断；网络错误、旧身份或旧咨询的迟到响应不能解禁。已有云信在线连接的远端撤销仍需另行接入验证，客户端前置检查不能防止持有旧凭据的修改版客户端直连供应商。

## 未知结果与生命周期

CREATE/TRANSFER/CLOSE操作持久化尝试、租约与结果。HTTP超时、传输失败、DB回写不确定或过期RUNNING不能证明远端动作停止，进入人工核验并阻止自动重建/冲突操作/无条件重试；纯当前尝试的IDENTITY_PENDING可安全退避。

本地advisory lock只提供进程间互斥，不是供应商fencing。未知结果下暂停UI发送不等于已撤销远端成员权限。安全解除核验状态仍需供应商结果依据。

正常关闭先核Team归属，再解散并精确回读；V2查询只有HTTP200且业务码108404才证明Team不存在，109404（成员不存在）、通用414及网络错误不能作为终态依据。已记录Team的有限CLOSE人工对账绑定原操作、咨询、Team、版本及租约，仅做一次只读确认；确认不存在后同事务完成终态、事件、审计与一次负载释放，不再次解散，不开放通用未知结果自动重试。

客服presence为账号级状态，`version`用于连接/可用状态条件更新；接单、结束及转交只改变`active_load`，不推进连接版本。客户端提交当前版本，过期写返回409，不自动取新版本重放旧离线状态。服务停止不代表presence立即离线，接待资格仍受最近连接时间限制。

客户端按身份/咨询代次隔离迟到响应、历史和实时消息及草稿；关闭窗口不重复创建客户端。已结束咨询可显式进入“再次咨询”并选择类型，提交沿用既有创建/恢复入口；窗口重开、刷新和类型选择不自动建立新咨询。后台恢复与订单清扫均在连接池结束前停止调度并等待在途工作。

管理端复用`/session`刷新权限，独立于SDK是否就绪；客服页因read撤销而关闭后，工作区仍保留恢复发现。并发刷新合并，认证变更期间延后确认；跨标签锁定/解锁及401/423推进失效代次，旧响应不可回写，排队的追尾确认同样遵守认证变更窗口。轮询间隔约5秒，不承诺后台休眠或网络异常时的发现时限，也不代表远端撤权完成。

read客户端身份与send能力分离：只撤接待权限时保留合法连接、历史和草稿，撤read或会话失效时清理敏感状态。`im.support.accept`同时是SERVICE和COMPLAINT的前置权限，COMPLAINT另外要求`im.support.complaint`。发送结果按当前身份/咨询/能力隔离，加载状态由请求所有权收尾，旧请求不能清掉新操作的加载状态。

## 供应商事件入口与首响事实

- 订单群首响以供应商签名事件为准：群消息抄送（`eventType=1`/`convType=TEAM`）是投递事实，群消息发送前置回调（`eventType=2`）是发送时授权事实，两者为独立处理器与ACK协议。入口默认关闭，仅显式配置（`ORDER_IM_EVENTS_ENABLED`及独立AppKey/Secret）时挂载；抄送持久化最小事实后才返回200，失败返回503（不返回会被视为成功的500）；前置回调按自身errCode协议拒绝，绝不使用会让客户端假成功的`responseCode=200`。
- 最小事实存于`zzsh_order.im_order_event`：批准按`(app_id,team_id,sender,msgidClient)`幂等并保存最小可复核授权依据（平台主体、成员/权限依据），投递按`(app_id,team_id,msgidServer)`唯一；重复投递对来源按官方别名规范化后比较，缺失的旧metadata保持可读且不改写，真正冲突只落一次证据并进入待核验。当前云信V2回调来源枚举为`AOS(1)`、`IOS(2)`、`PC(4)`、`WEB(16)`、`REST(32)`、`MAC(64)`、`HARMONY(65)`；仅已知非REST来源可作为首响必要条件，未知/缺失/非法来源不计首响，但不单独禁止原合同允许的正常聊天。只有已验人工投递（发送者为本单JOINED客服、批准与投递消息类型相同、已签名发生时刻符合关联窗口且授权依据完整）才写入首响，买家/号主、SYSTEM/REST机器人与系统通知不计。可信身份的历史投递按批准与成员时间线判定，不因当前身份映射状态直接丢弃；同键出现拒绝或关键字段矛盾时进入待核验，旧批准不构成永久通行证；首响取所有已验事件的最早发生时刻，首次确认即永久停止自动补派，更早的合法迟到事件只单调前移并审计，不重启补派。数据库另以守卫约束绑定同App/同订单/同Team的已验投递，证据行不可改写，首响时间只能对应其事件并单调前移。
- 云信抄送地址校验可发送已签名的新鲜空正文POST；该精确copy路径在验签、App绑定和新鲜度通过后应答200，但不解析为消息、不写业务事件/首响/成功审计且不调用Provider。`{}`、畸形JSON和发送前回调仍按各自合同处理；发送前回调是否也有空正文地址探针尚未证实。
- 已安装V2 Web SDK在单次`sendMessage(message, conversationId, params)`中接受`params.routeConfig.routeEnabled/routeEnvironment`。默认不传路由；仅服务端精确授权的App/订单/Team/会话可将测试环境作为该条消息参数。服务端BOT走独立消息接口并使用独立顶层`route_config`，不因SDK设置自动路由；代码配置不证明控制台环境已经配置。
- `first_response_state`默认`NOT_STARTED`；只有启用事件入口后新READY的群才在同事务激活，历史群不批量启用。`NOT_STARTED`只停止该群的首响跟踪与计时，不改变合法成员原有聊天授权。单条消息查询与2/4分钟提醒补派已完成本地受控验证，真实供应商事件与外发尚未验收。
- 验签与请求新鲜度分离：错签/跨App拒绝。抄送通道中已验证签名的已见重送按去重处理，可信但超窗的未知事件进入受限核验（不直接确认首响，也不当作错签拒绝）；前置回调通道是发送时裁决，过期请求一律按协议拒绝，不重放旧批准、不新建可关联批准，新鲜的重复请求仍按当前资格重新裁决。批准与投递的关联只比较已签名消息的发生时刻，不受网络传输延迟或到达先后影响。

## 配置与验收范围

`YUNXIN_ENABLED` 不再是默认关闭的显式开关：配置 `YUNXIN_APP_KEY` 与服务端 `YUNXIN_APP_SECRET`（或 `YUNXIN_APP_SECRET_FILE`）即启用真实provider，这是部署环境常态；两者都不配置时保持离线，不装配provider、不签IM凭据。显式`YUNXIN_ENABLED=false`与完整凭据并存视为配置错误而非静默关闭；`APP_PROFILE=migration`拒绝装配真实IM。业务侧默认走真实通道，离线测试靠“不提供凭据”保持可复现。填写凭据本身不构成真实调用授权，真实App验收另计。测试provider/消息transport必须显式注入且具有受限test/fake能力，不能作为生产降级数据。

## 巡视、统计与最小售后记录

- `GET /api/v1/im/admin/audit/conversations` 要求 `im.support.management.read`，支持 limit/cursor、type（SERVICE、COMPLAINT、ORDER）及 adminUserId。省略过滤表示全部；过滤条件变更须丢弃旧游标。订单活动时间优先消息活动，再建群/建单时间。historyState 区分 AVAILABLE、NOT_ESTABLISHED、LEGACY_UNAVAILABLE、RECOVERING，不把缺历史当零消息。巡视不改已读或派单；旧轮次保留的独立 Team 按精确 App/轮次绑定与远端标记复核读取，不借当前线程替代历史。
- `GET /api/v1/im/admin/support-overview` 要求管理读取，支持下述时间范围，默认北京时间今天。reportDate/serverNow 来自服务器。期间接待次数/用户只计发生接待动作的咨询，不含订单群；hourly为期间CREATED/REOPENED新轮次的小时分布。排队只统计当前有用户首条消息、未指派的WAITING；可接待须AVAILABLE、CONNECTED、2分钟内心跳新鲜、云信身份READY且具备读取/接待权限，顶部“当前可接待客服”与派单资格同口径。首响askedCount为期间首次提问的咨询数，sampleCount为已人工首答数，pending/overdue和关闭未答不能冒充已答样本。
- `GET /api/v1/im/admin/my-support-statistics` 经管理BFF转发，仅GET，支持下述时间范围，要求 `im.support.read`；身份固定为当前管理员，不接受指定员工。返回reportDate/serverNow/period、today{seconds,sessions,users}、current{consultations,orderGroups,unread,oldestPendingAt}、ratings{count,average,distribution}和firstResponse{sampleCount,averageSeconds}。个人首响只计本人是首次人工回复者且回复发生在期间的样本，不按最终接待人代计，可含跨期提问。oldestPendingAt是当前仍有未读的接待轮次之首次用户提问时间，不是最后一条未读消息的等待时长。
- 最小售后记录仅绑定 NATIVE 已确认 POSTED 结算订单，租客/号主各自可提交；结算后即可提交，不另等72小时。用户 `GET/POST /api/v1/im/user/aftersales`（GET 必须 orderSource=NATIVE、orderId）只返回本人记录。管理 `GET /api/v1/im/admin/aftersales` 和 `POST /:id/claim|contact|resolve` 复核读取/接待及责任范围。描述/结果上限1000字，同人同单至多一条 PENDING；处理后可新提交，仅 PENDING/RESOLVED 两状态。创建/处理用稳定操作 ID，领取/处理核版本；处理完成保留历史处理人。
- 售后沟通复用已有 SERVICE 咨询和转交机制，没有新工单消息系统。待处理记录随当前咨询责任变更，已处理记录不跟随；contact 只有 ACTIVE、本人接待、READY、可发送时才成功，否则保留记录并返回可恢复结果。记录处理状态不代表退款/到账，不创建资金事实。
- 订单群 access 返回 serverNow 与 terminalSendAllowed，由服务端判定沟通窗口。邀请运营复用现有成员邀请接口：在租群及终态合法沟通窗口内可邀请，终态还须当前有效 STAFF 成员可读；每次仍检查会话、范围、群绑定和目标资格，窗口到期拒绝。平台 availability 仅表达本平台接待偏好，不等于网易云信实时在线。
- 押金展示复用结算/取消既有退款路径，结算退款已含 depositRefund。不新增独立退押金执行；登记应付、渠道状态与到账未知保持分开，不能重复创建押金退款。

租期到期提醒重试前会复核当前时段；旧时段任务跳过后续投递（STALE_BUCKET），避免到期后再发送“24小时内到期”。跳过不代表既往未知尝试从未送达，也不改变订单状态或自动结束租期。

## 客服统计时间范围

客服统计与我的接待的管理GET接口均接受 `dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD`，起止为北京时间自然日、均包含，单次1–366天。默认由服务端取今天，旧 `date` 单日兼容；不得混用、缺一端或传重复参数。响应 `period{dateFrom,dateTo,days,timeZone,trendFrom,trendTo}` 描述真实范围，`reportDate`保留为结束日期兼容字段。显式区间趋势覆盖整个区间，默认/旧单日保留截至所选日的7天趋势。

历史名 `today*`/`transfersToday`/`handoversToday` 及个人 `today` 表示所选期间，界面须随范围改标签。期间咨询/用户统一去重，评价与时效按原始样本聚合，接待时长截取与窗口重叠部分；不能相加每日去重数或平均每日均值。hourly为期间各小时新建咨询总量，不是日均。队列、可接待人数、当前负载/负责订单群与个人current待办继续实时，不伪称过去时点快照。个人接口始终只返回当前登录客服，无指定员工参数。

团队首响按期间首次提问的咨询统计，个人首响按期间由本人首次回复的咨询统计、可含跨期提问；二者统计口径须通过简短标签/帮助信息区分。时间范围不扩大管理权限或对象范围。

## 会话阅读抄送接入

- `POST /api/v1/im/read-events/copy` 接收当前云信 App 的会话已读抄送85，限现有咨询与订单 Team。按原始请求体验证 AppKey、MD5、CheckSum 和5分钟请求新鲜度；仅已启用本平台接收配置时接受合法的空请求/空对象地址校验。配置默认关闭，不要求部署时即开通云信控制台。
- 管理 `GET/PUT /api/v1/im/admin/read-copy-settings`（BFF为 `/api/bff/admin/im/read-copy-settings`）提供开关、HTTPS公网 origin、派生的回调地址、最近地址校验/合法事件时间。读取要求管理读取权限，写入另需 `im.support.integration.configure`；原欢迎语配置权限不包含接入配置。写入核版本及原操作ID并审计，不返回或通过页面收集AppSecret。保存不修改云信控制台、不发起任意URL探测，也不证明公网可达。
- 85的 `ackMsgTime` 是已读消息位置，不是回调到达时间。按精确 App、READY身份映射和当前会话/订单成员关系保存单调位置；咨询管理员还须是当前接待人并具有读取/接待权限，订单管理员另核游戏范围。SYSTEM、冻结或无关身份不推进状态；重复及较旧回调不重复清除未读。只在阅读位置覆盖最新已知消息时清相应成员未读，保留新消息未读；不改变业务版本、排序、首响、订单或资金状态。
- `receiverReady`只表示服务端已装配接收器。`WAITING_FOR_CALLBACK`表示等待云信回调，`CALLBACK_OBSERVED`表示曾收到合法地址校验或85事件，须结合最近时间展示，不等同于当前连接健康或所有消息已同步。平台接收开关与云信侧开通、域名/反向代理部署分别完成，单条消息的群已读人数/成员不由85推断。
- 实现及隔离验证不等于公网接入验收；生产/测试云信的真实回调仍须在目标部署后独立验证。消息撤回保持120秒，不因本接入延长。

用户在咨询中选择“关联订单”后立即单独发送订单卡，不清空或发送当前文字、引用和附件草稿。卡片复用订单阶段卡的外观，仅展示名称、公开订单号、租入/出租身份和站内详情入口，不提供履约确认或资金操作。
