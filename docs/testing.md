# 测试、验证与验收脚本规范

状态：**v1.0 / 联合评审定稿**。生效日期：2026-10-09。

本文用于后续开发、评审和测试维护；文档定稿不等于已经提交Git。它不是现有窗口的追加许可，不改变已接受证据或正在执行的测试范围。

目标：用最少的可靠检查证明业务正确，优先核心流程、资金、权限和并发。测试数量、截图数量、封包文件数量都不是质量或合并指标。

适用于后续任务和测试维护。已签发或执行中的资源窗口保持原约束；调整执行方式须明确重新绑定，不得用本规范跳过原保护。资源、认证、秘密和进程管理仍遵守 [本地环境](local-environments.md)、[PostgreSQL](local-postgresql.md)、[测试登录](local-test-auth.md)。本规范不授权连接生产、真实渠道、建库或删除材料。

## 1. 测试依据

每个新增测试须说明：业务规则/接口合同、风险、输入、可观察结果、验证层级。正常路径加有实际风险的失败边界即可，不为每个私有函数、样式或实现分支机械添加用例。

优先级固定为：**交易与资金正确性 → 身份/权限及数据保护 → 本次改动的核心操作 → 非关键视觉细节**。“快速”指选择足够证明风险的最小验证集合，不是用mock替代真实数据库，也不是删去失败路径。

### 新增必要性判断

新增测试、测试工具或临时脚本前，在任务说明或变更说明中简答三项即可，不另建审批系统或证明文件：

1. 它能发现哪一种具体的业务错误或当前工具缺口？无法说明则不新增。
2. 已有用例、正式入口或标准工具为何不能覆盖？可以扩展就不重复创建。
3. 最低成本的充分验证在哪一层？明确通过条件、实际依赖和维护归属。

原任务评审者在既有变更评审中核对这三项，不新增审批节点。不能说明具体风险或工具缺口的新测试/工具，不作为长期交付保留；原诊断和失败证据仍按保全范围处理。

不为纯实现细节建立测试，不为已经被同层同路径充分覆盖的风险重复建套件。一个规则在纯函数、API和浏览器中同时出现时，每层应证明不同风险，而非三次复制同一算例。遇到真实生产边界，必要集成测试不能以“已有单元测试”为由省略。

- 优先已确认业务合同、服务端接口与数据库不变量。实现代码不是唯一正确性依据；金额期望用独立算例或已核业务金样，不能让待测函数生成自身期望。
- 金样由对应业务模块维护者在既有测试注释或fixture中记录规则版本、来源与独立期望；不另建金样审批平台。输入构造复用正式工具是允许的，不等于期望由待测函数自产。
- Bug回归使用能够复现原错误的最小真实调用路径。已有测试能扩展就不另造探针框架。
- 内部状态、HTTP响应和客户端投影分别按各自合同验证。`ready:false`、`reasons`不自动等于本次命令失败；内部Command不直接与公开投影比较。
- 测试权限、幂等、UNKNOWN、并发与精确金额属于核心业务，不因精简而移除。

## 2. 分层与既有工具

| 层级 | 应验证什么 | 使用方式与不能证明的内容 |
|---|---|---|
| 纯规则 | 定价/舍入、结算分配、等级窗口、状态转换 | 复用 `node:test` 和 `assert`；不接DB。不能证明SQL、权限或真实锁 |
| API＋真实PG集成 | 正式路由/DTO/鉴权、事务/约束/幂等/审计、读取投影 | 复用 `createApp`、既有资源与正式迁移；HTTP可用现有fetch。不得用内存SQL模拟代替PG通过 |
| 组件行为 | 身份切换、错误/空态、原意图恢复、表单行为 | 复用现有React测试装置；不把源码正则或CSS token断言当交互证据 |
| 浏览器关键流程 | BFF与API接通、实际可操作性、主要数据和状态可见 | 使用既有浏览器工具；优先role/label、条件等待。只选必要用户旅程，不在每个视口重复资金写 |
| 外部适配 | 汇聚/云信/OSS协议、签名/回调/错误/去重及实际权限 | 日常用明确fake；获批后用独立provider-test验证。fake成功不是渠道成功 |

不设固定测试层比例。对本项目，真实PG/API边界价值高于大量手写执行器模拟。保留现有Node/React工具，不因官方教程使用Jest/Supertest而全仓迁移。浏览器框架的自动等待、fixtures、trace等能力优先于自建同类工具；是否新增依赖按实际缺口决定。

证据等级按实际入口、导入闭包、继承环境和资源开关判断，不凭文件名中的 `offline`、`integration` 或 `postgres` 判断。先选文件和核其顶层/setup副作用，再用测试名筛选；名称筛选不会阻止模块顶层代码执行。编译、fake readiness、内存SQL及组件mock各有价值，但都不是实际数据库或渠道证据。

## 3. 核心验收清单（按本次改动选择）

| 业务域 | 最小关键断言 |
|---|---|
| 上架/目录/报价 | 正式目录和媒体权限、核价/条款/发布版本一致；失效版本不能下单；正常/自定义/极速的计算边界用低层测试覆盖 |
| 建单/支付/履约 | 本人确认、占用单赢家；同请求付款不重复；期初双方确认；正常结束以及受影响的提前/人工分支；群/成员权限只验证该改动相关范围 |
| 资金 | 原付款分配闭合、逐经济事件借贷相等、主体/来源/版本正确；费用不重复；应付退款不等于渠道到账，UNKNOWN单列；重复/并发零双记，失败原子回滚 |
| 提现/保证金/分佣 | 已收/占用/应退/已退分开；失败释放与UNKNOWN原请求核对；引用原资金来源；收退与钱包revision的相互隔离 |
| 权限/身份/审批 | 跨主体与无scope拒绝、自审/撤权/过期拒绝；批准不等于已执行；认证失效隐藏私有投影但保留未决写责任 |
| 迁移 | 空库正式schema、已有前缀前向升级、真实旧样本关系/金额/密码兼容；重复不双计，冲突隔离，不伪造来源或重算旧单 |
| UI/报表 | 关键操作、加载/失败/未知、金额与API一致；图表/明细/导出同口径；关键页面响应式和键盘路径 |

单个改动不必重做整表。各业务域先有可独立验证的真实PG/API套件，再保留必要的跨域旅程，覆盖原付款依据→结算→分佣/提现的关联；巨型旅程不是唯一资金证据。

并发单赢家需两个正式业务调用及最终状态证明。锁测试可以由受控第二事务持有真实争用行，但需确认业务已到达同步点、目标阻塞关系或数据库等待，再检查释放后结果。允许有界轮询和超时，禁止仅凭100ms等固定时长内没返回就认定目标锁成立。涉及窗口、过期和保级的时间规则优先用注入时钟/固定时间fixture，不改写系统时钟；真实DB时间边界仍需对应集成验证。

### 交易与资金不可降级的断言

适用于本次改变的资金路径；不要求每个非资金改动运行全部金融套件：

- **算得对**：独立预期、精确分/decimal、舍入位置与费用归属正确；付款分配、退款责任和各钱包读回相符。
- **记得对**：每个经济事件逐笔平衡，主体、币种、原付款/退款/结算依据及版本绑定正确；总额相等不能掩盖错人、错来源。
- **不超额**：累计占用、释放、退款和冲正不得超过对应来源的可用/剩余责任；对本应非负的可用额/占用额断言非负，合法债务与冲正不得被截成0或误判异常。并发使用不同key也不能绕过累计约束。
- **只做一次**：按正式幂等范围绑定realm、主体、操作、资源及key，在当前授权通过后，同指纹返回原结果，同范围同key改正文拒绝。另一主体不能借同key读取他人结果；不同接口采用各自正式范围。重复回调、并发请求、过期worker不能重复记账。
- **失败不半成品**：事务明确失败时业务与分录一起回滚；提交未知时保留原责任，不伪造失败或新key重试。
- **只有有权主体能做**：相关跨用户/跨游戏/失权/过期/审批越界负例必须验证；前端隐藏不是权限证明。
- **结果说清楚**：受理、处理中、内部记账、应退款、渠道成功和UNKNOWN分开；用户、管理端与API一致。

提现超时保持原占用及请求责任，不因超时释放。只有正式证据确认未出款、实际划出额和手续费符合未出款合同，才释放一次。金额/币种/来源不匹配或相反终态进入对账，不追加第二笔资金处理；查询、回调、重复与乱序分别按正式状态机验证。

一个可组合的领域测试即可覆盖多项断言，不必每项新建测试类。默认使用“安排输入→正式操作→验证结果”的短流程；一次独立领域失败不应迫使其他已接受领域重新付款或重置。

## 4. 环境与脚本边界

区分可重置自动回归资源与保留人工验收资源：前者按已授权精确清单隔离/清理，后者保护已接受对象、原回执和责任，禁止整套reset测试接入。测试隔离优先独立数据/事务/资源和最小权限，不在每次SQL前额外包自定义IPC证明。

普通测试的默认执行方式：一个测试文件或既有npm入口＋共享setup/teardown。环境setup只负责指定配置、资源身份、正式迁移/fixture和精确清理；业务由正式API/服务调用，不在runner复制状态机、金额公式、鉴权、SQL解析器或自建路由代理。

新增测试/验收脚本必须满足：

1. 能说明现有工具缺什么；适用单一当前需求，有固定输入、明确退出码、有限超时、失败原始诊断及finally清理。
2. 使用现有应用工厂、事务/资源/认证工具，适配外部依赖时只替换外部边界，不绕过要验证的正式业务模块。
3. 没有真实需求不新增RPC总线、逐SQL拦截、通用审批解释器、重复时钟/租约系统或多层“测试执行器的测试”。确需安全工具变更，按工具自身风险验证一次后复用。
4. 长期回归归所属 `apps/*/test`，共享生命周期小工具才进 `scripts`；临时研究/诊断放 `tmp`。有价值临时反例归入正式用例后，临时入口退出日常门槛。
5. 不把同一套源/运行器层层复制到每轮目录。保留一份当前输入清单、原失败和必要历史引用；源码/构建变更重新绑定，无变化复用已验证证据。普通日常测试不要求每次哈希全部构建产物。

测试装置可用小型手写fixture验证单个拒绝或UI状态，但不能把独立手写的整段成功DTO流程当正式装配证据。接口形状应通过正式解析器/投影/命令或经校验的脱敏真实样本对齐；金额期望仍需独立。复用产品函数不代表相应网络、SQL、锁和身份也已真实执行。

工具故障的回归须经过发生故障的实际配置传递、启动、IPC、序列化或投影边界；fake直接返回READY、锁证明true或页面成功，不能覆盖这些机制。优先把永久反例纳入现有领域测试，而非继续扩一层fake执行器。

合成回归测试可以使用已登记、事先批准的长期测试范围，不默认每次执行都设计一份单次审批包。保留历史/资金验收资源、真实渠道或受控维护写仍按具体任务授权。已消费的单次许可不会因本规范自动恢复。

这里的批准可由原任务或资源使用约定一次覆盖，无需每轮重复申请；仅登记资源名称不等于获准重置或执行任意写入。隔离也不等于授权。退役守卫前，在原变更说明中简述“原风险→现有替代→拒绝证据”：资源身份、持续有效的锁/租约（若原合同要求）、权限、越界写和未知责任要有等效保护。标准进程工具不自动提供这些边界；GET也可能含ensure写，不能只凭HTTP方法认定只读。

## 5. 生命周期、失败与重试

- 启动前核最终配置、依赖和路由装配，运行真实配置解析器；复用稳定local-auth，首次秘密先保存后请求。优先单独完成环境可用性检查，再开始业务验收，避免先做大量业务才发现未挂载路由。
- 生命周期工具只管理自己启动的PID/连接/浏览器；标准进程与数据库能力能完成就不造监督器。锁、身份、DDL权限或租约本身是本次待测需求时，才加针对性测试。
- 区分产品缺陷、测试预期缺陷、环境失败、外部服务失败。断言失败不自动意味业务未受理；HTTP/数据库原回执先保全，再分类。
- 普通独立合成用例可按已授权隔离方式重新运行。保留资源中的未知写不盲重试，不换key；原同key重放/查询仅在正式幂等合同和当前许可允许时进行。
- PostgreSQL可重试事务错误只按正式服务策略重试完整事务；COMMIT结果未知、HTTP超时或外部渠道请求不等同“事务已回滚”。
- 浏览器条件等待可重试观察，不等于重发付款/退款/发布。自动重试通过仍记录首次失败及flaky，不掩盖问题。
- 普通失败无需反复全库备份；迁移、维护改写或保留资源验收按风险指定恢复点。已有合法业务或渠道效果不能仅靠restore回退。
- 原始日志/错误码、请求标识、主体/对象/版本和前后责任足够支撑定位；trace、storageState及请求头可能含秘密，受限保存，公开报告脱敏。

## 6. 重跑与合并门槛

每次先选受影响用例；该层通过且无新的改动/失败/依赖变化时停止扩测。不能为了让报告更长追加检查。若无法判断影响面，明确原因后扩大到所属模块，而非无条件从全平台重跑开始。

| 改动 | 默认检查 |
|---|---|
| 文案/间距/颜色 | 对应页面实看、受影响静态检查；不新增只验证实现的测试，不跑PG/资金 |
| 组件交互/BFF | 对应组件/路由回归、必要浏览器主路径；BFF需核真实API形状 |
| 规则/资金/权限/SQL | 相关纯规则＋真实PG/API正反例，资金/并发改动必须有真实断言 |
| 迁移/ACL | 空库及受影响升级路径、旧行/约束/权限保护，不要求无关页面重跑 |
| 测试工具小修 | 复现原工具错误的直接检查＋相关实际装配验证，不默认重跑产品全root |
| 最终跨模块候选 | 相称完整回归与受影响组合路径；候选/依赖没变就不重复全量检查 |
| 新增或迁入长期测试 | 接入已有入口，或标明父套件、资源开关与调用方式；不把导出的验收helper重复登记为独立套件 |

日常优先已有窄入口或对应构建文件，不默认跑整套。现有 `npm run check:offline` 是综合检查入口，包含构建和smoke临时服务；个别测试可能受继承的环境变量控制进入PG，名称不是零连接保证。`npm run check` 增加 `test:db`，也不等于运行全部资金或IM套件。两者主要用于适当的最终跨模块候选，执行前核资源与条件分支；以实际package为准，不发明尚未接入的入口。

条件性PG/资金套件未进入时必须记NOT_RUN，根命令或CI通过不能替代它。改动影响的资金、事务、并发或权限边界必须有相符的真实验证；缺失则阻塞对应能力验收，不能用一句“豁免”替代。独立默认关闭代码可按下述规则评审合入。

复用结果必须匹配被测源码、相关依赖、配置/schema与证据等级；只看HEAD相同不够。环境失败保留原结果，定位后只补受影响检查，并解释是否使旧证据失效。不以任意覆盖率、固定用例数量或必须跑满多少分钟作为门槛。

同次候选可复用一次已绑定构建，避免API test后再无变化重建API；不能跳过必要编译使用旧dist。无关历史失败须用来源和差异证据证明不在本次影响面，单列追踪，不自动豁免，也不冒称整套PASS。

合并阻塞：错误资金/权限、可复现核心流程失败、迁移不兼容、未知写责任未分类，或本次改变的关键接口未经真实集成验证。非阻塞可后置：不影响操作和数据理解的样式细节、无关历史模块、未纳本次启用范围的外部渠道验收。后置必须明示限制；未验真实渠道的能力不得开启生产。

新功能默认关闭且不改变现有路径时，可单独评审基础代码合入，不能宣称功能已上线。Git合并、部署、schema升级、功能启用与渠道验收分开。

### 既有测试维护

先标出重复、脆弱或无业务依据的检查及使用者，再合并/替换；保留等效核心断言后才能退役。不能因测试红了或执行慢就删除它，也不能用本规范批量清理tmp、秘密、备份或历史失败证据。现有受保护检查点收口前不替换执行体系。

优先检查既有资金用例是否只有总额/计数而缺主体、来源和累计边界；在原测试中定向补强。没有正式入口的有价值用例先补入口或明确专用调用，不直接再写一套。源码文件存在、入口可达、某轮实际执行通过是三个不同事实；无法据入口缺失推断历史上从未手动执行。

## 7. 最小交付

一份简短结果即可：候选版本与变更范围；风险→实际测试→关键断言；结果/耗时/证据路径；NOT_RUN及其影响；未决责任和资源状态。用“原金额分配闭合、重复不双记、跨主体拒绝”等结果表达价值，不只给“几百项PASS”。

正式构建和浏览器截图绑定同一候选。只复跑受影响部分时保留上一轮完整检查与本轮差异；不改写失败日志、不把修复后结果覆盖成原记录。

## 依据

这些来源支持分层、真实边界和用户行为测试；本规范的资金矩阵、授权和资源规则是本项目工程取舍，并非官方要求使用我们的单次窗口或执行器。

- [NestJS Testing](https://docs.nestjs.com/fundamentals/testing)：既有应用模块装配、替换依赖和HTTP测试。
- [Node.js 24 Test runner](https://nodejs.org/docs/latest-v24.x/api/test.html)：原生测试、hooks、mock、按名称选测；只用仓库锁定版本支持的功能，不因网页新版本升级运行时。
- [Playwright Best practices](https://playwright.dev/docs/best-practices)：用户可见行为、隔离、稳定定位和条件等待。
- [Playwright Web server](https://playwright.dev/docs/test-webserver)：复用框架服务生命周期能力，端口归属仍遵守本项目规范。
- [Playwright Retries](https://playwright.dev/docs/test-retries)：失败与flaky分开；不能据此盲重发资金操作。
- [Testing Library Guiding principles](https://testing-library.com/docs/guiding-principles/)：围绕实际组件使用方式验证。
- [PostgreSQL 16 Transaction isolation](https://www.postgresql.org/docs/16/transaction-iso.html)：事务隔离和并发语义。
- [PostgreSQL 16 Serialization failure handling](https://www.postgresql.org/docs/16/mvcc-serialization-failure-handling.html)：正式事务重试应覆盖整笔事务；HTTP/COMMIT未知保全是本项目额外的业务约束。
