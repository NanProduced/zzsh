# 本地开发环境使用规则

适用于 API、用户站、管理站及其测试进程。所有 agent 启动、停止、重启、迁移或重置前必须遵守；具体启动方式见[开发说明](development.md)。

数据库命名、资源集复用、登记和任务结束清理遵守[本地 PostgreSQL 使用规范](local-postgresql.md)。同一任务返修不逐轮创建新库，当前数据库清单统一维护于主检出tmp/postgresql-resources.md。

## 固定端口与环境归属

| 用途 | 用户站 | 管理站 | API | 维护者 |
|---|---|---|---|---|
| 主开发环境 | 127.0.0.1:3100 | 127.0.0.1:3101 | 127.0.0.1:3102 | Master，或本次明确指定的环境维护者 |
| 独立分支预览 | 4200+10n | 4201+10n | 4202+10n | 已登记的分支执行者；n为0–9，同组一起预留 |

PostgreSQL固定127.0.0.1:55432，Redis固定127.0.0.1:56379，Compose项目为zzsh-rebuild-local。不得占用或复用其他项目的5432/6379。应用默认只绑定127.0.0.1，不为方便使用0.0.0.0。

3100/3101/3102是主环境规范，不代表它们当前已启动。已有其他端口的Owner验收环境由Master登记为保留环境，迁移到标准端口需单独安排，不得为了“规范化”直接停止。端口范围只是项目预留，仍须检查是否被其他程序使用。

## 启动前先查，不默认启动三端

1. 阅读主检出根目录下的tmp/local-environments.md，核对环境维护者、工作树、端口、数据库及用途。独立worktree也查询这份共享登记，不各写一份互相不可见的端口表。
2. 检查所需端口是否监听，核对PID、启动时间、工作目录/脚本和服务来源；不输出可能携带凭据的完整命令行或环境变量。PID可能复用，不能只看旧登记的PID。
3. 已有服务符合任务的源码与环境要求时直接复用。只有端口相同或health返回200，不足以证明是本任务的版本；不符合时联系维护者或另建已登记的隔离环境。
4. 前端静态/UI任务只启动所需前端；API测试只启动所需API/依赖。没有实际需要，不运行根npm run dev同时启动三端。
5. 主环境没有服务时，由Master或指定维护者启动。普通实现/评审任务不隐含授权重启主环境；任务明确指定维护环境后无需再逐次询问。

只读查看端口可用PowerShell：

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object LocalPort -In 3100,3101,3102 |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

## 分支和隔离测试

- 分支预览必须使用独立worktree。先在共享登记预留未占用的一组端口，写明负责人/任务、路径、分支、用途，再启动；保留组内角色对应关系，不东拼一个API端口和另一个未知前端。
- 前端代理、BFF API地址、AUTH_API_ORIGIN、AUTH_USER_ORIGIN、AUTH_ADMIN_ORIGIN必须匹配实际端口。不得只换监听端口而继续连主环境数据库或其它分支API。
- 主机名统一127.0.0.1，避免localhost/127.0.0.1混用造成cookie和Origin问题。浏览器cookie不按端口隔离；不同环境使用独立浏览器profile/上下文，不能认为换端口已隔离账号会话。
- 数据库测试使用带标记的独立库与迁移/runtime角色。Redis有写入时也要隔离键命名空间，禁止FLUSHALL或清理共享业务键。测试不能使用Owner正在验收的账号。
- advisory lock与数据资源共同隔离。锁被占用先报告；不能仅换锁号而仍操作原库/原角色，也不能终止别人的锁持有者。维护流程需登记使用的库、角色名和资源锁，不记录密码。
- 自动化测试确需临时HTTP服务，可继续使用listen(0)等随机端口，不强制固定端口造成并行冲突；其进程/数据仍必须隔离，记录结果并由finally退出。不得因此启动额外长期三端环境。
- readiness测试会停止依赖，必须维护者安排窗口；普通UI或API检查不得随手运行。

## 启动、热更新和重启

- Vite使用明确端口并加--strictPort；Next/API发生占用应失败，不通过自行递增端口隐藏冲突。分支启动采用显式覆盖参数/本地启动配置，不修改提交的主环境默认端口。
- Vite/Next开发服务器一般自动更新页面；组件变更不需要重复启动进程。配置、环境变量、新依赖变更是否需要重启，以实际工具提示为准，交由维护者处理。
- API是否自动重载取决于实际启动命令。项目dev命令包含编译/watch；直接运行dist或临时server.cjs的进程不保证更新，重新构建也不等于正在运行的进程已加载新代码。
- 运行中的服务与测试不要在同一worktree并发重写dist/.next/node_modules：根build/check/npm ci可能破坏预览或改变被测版本。测试优先独立worktree；共享目录时安排维护窗口。
- 启动后验证监听归属、前端访问、API健康与对应版本，更新登记；启动失败先看该进程日志，不再反复启动副本。
- 长期服务用可管理的后台方式或独立终端，记录PID/父子关系与日志路径。Windows后台启动用隐藏窗口；不要让无限运行的命令占满执行工具导致agent卡住。
- 根npm run dev采用concurrently --kill-others，一端退出可能结束同组其他进程；只供明确负责整套环境的维护者使用，不用它附着或管理别人已启动的服务。

## 停止、数据与清理

- 默认只停止自己创建且本轮有清理授权的进程；停止前重新核验身份及子进程归属。不能按端口直接kill、不能全局taskkill node、不能全局Docker stop/prune。
- 重启不得隐含重建数据库、重发Boss凭据、重置密码/PIN/TOTP或删除卷。先读启动脚本；若脚本会初始化/清库，应使用可恢复启动方式或取得对应数据操作授权。
- 迁移由维护者对明确目标执行，普通前端验收不自动迁移。新迁移先隔离验证；若变更会使现有主环境不兼容，在brief说明，不偷偷替换运行环境。
- 测试结束关闭自己创建的HTTP服务与临时上下文，按测试契约保留或清理隔离资源；Owner需要继续验收的预览交接给维护者后再结束任务。登记状态更新为已停止/已交接。
- 清理worktree前先确认其中服务/工具已释放工作目录、改动与过程证据已保留。未知残留不强删，自动审批阻止操作时明确说明。

## 登记和交接

共享登记固定为主检出tmp/local-environments.md，由维护者维护；分支执行者只更新自己的预留记录，不覆盖他人记录。出现多人申请同组端口时，维护者分配后才启动；登记本身不替代启动时的占用检查。

每个长期环境至少记录：用途/状态、维护者及任务、工作树与分支/HEAD、三端端口与代理目标、启动方式与是否watch、PID与启动时间、数据库/角色/锁或其受限配置路径、浏览器隔离方式、日志路径、是否允许关闭/重置。不得记录AccessKey、密码、cookie、Token或签名URL。

正式文档只保留规则，实时PID、分支预览、日志、临时配置、测试证据放tmp。不得把此登记当成免审计或认证绕过的授权。
