# 洲洲商行用户端设计

状态：用户端设计约束，适用于 apps/web；不代表所有页面已经实现或通过验收。管理端的产品与设计规范独立维护。

## 视觉方向与范围

保留已形成的首页框架、洲洲 IP 和品牌识别；当前主要优化功能页和业务流程，不整体重做首页。门户保留游戏氛围，市场、交易、个人中心和资金操作优先保证信息可读、任务清楚与反馈明确；具体游戏的素材与色彩限定在相应业务场景。

平台在深浅主题下使用中性的背景、文字和层次，品牌暖金用于主要强调，游戏专区可使用对应的局部强调色；沿用现有主题 token，不为单个页面另建全局主题。Logo 和洲洲形象复用 [品牌物料](../../assets/brand/README.md)，不描摹参考图中的品牌或伪造账号、库存与凭证。

## 页面与任务

- 首页继续作为服务门户，保留现有导航、服务入口、轮播和个人入口的整体框架；宽屏以服务导航、轮播、个人入口分区，窄屏按现有布局重排。轮播可操作，内容与图片以实际配置为准。
- 市场通过搜索、筛选、排序和结构一致的账号卡帮助比较；账号详情分清当前资源、费用、租赁条件与图片，公开资料和私有凭证分开。
- 上架采用清楚的分组、草稿与提交前检查；校验信息靠近对应字段并帮助定位，草稿与服务端已发布事实分别呈现。
- 个人中心分别组织租入订单、出租订单、我的账号、钱包、会员、邀请及安全；同一用户可同时是租客和号主。订单突出当前阶段、轮到谁、下一步及相关沟通。
- 钱包、提现和收益页面将可用余额、记录金额、待处理和渠道结果分开；帮助中心和规则页面以可搜索、可阅读的结构呈现，不以装饰压过正文。

## 组件、色彩与排版

- 先复用现有组件和 [全局样式](src/app/globals.css) 中的主题、字体及状态 token。用户端功能页以 HeroUI v3 作为展示性组件基线，并兼容既有 Radix 认证、抽屉、弹层与客服入口；不为了参考图引入第二套主题。
- 中文正文、金额、条件及状态使用清晰的文字层级；展示标题可体现游戏气质。金额显示最多两位小数并按规则四舍五入，计价与账务真值由服务端决定，不能用显示值反推冻结金额。
- 按页面任务安排主次操作，按钮、输入、选择器和弹层保持明确可操作状态；颜色不能成为区分状态或传达错误的唯一方式。避免用内部状态码、数据库字段或无意义说明替代用户语言。
- 可复用的页面、列表、表单、弹层及反馈模式以现有实际组件为起点；确有缺口时再增补，不因参考素材更换整套组件或品牌资产。

## 状态与交互

- 清楚区分付款、开租、结算、退款申请、余额入账和渠道到账；本地记录或处理中不代表真实到账。旧单的原始记录、下单冻结资料与迁入时账号资料分别表达。
- 已知为零、暂无记录、未读取、读取失败、无权限和待核实分别展示；历史数据中可用的字段正常显示，缺失或来源不明时不补造。
- 提交、加载、成功、失败、禁用和结果未知均有清晰反馈与可用的恢复路径；不以反复点击或新请求掩盖结果未知。需要确认的操作应解释影响，实际授权、金额和最终状态由服务端决定。
- 登录后尽量回到原任务；跨用户、账号切换或权限变化时不能继续展示上一主体的私有信息。订单内沟通、客服提醒与业务确认是不同操作。

## 图片、动效与适配

- 复用已授权的品牌素材与真实公开资料；官方角色、皮肤和外部素材按实际来源与许可使用。生成式示意图不是业务事实或已上线功能。
- 动效服务于反馈、状态或品牌表达，不干扰表单与数据阅读；减少动态偏好下提供稳定表现。轮播应支持键盘和触屏操作。
- 电脑、平板和手机都要能够完成适用的主要任务；窄屏按内容优先级重排、收纳筛选与辅助信息，核心操作不依赖悬停。
- 根据改动验证深浅主题、代表性视口、键盘焦点、对比度、图片失败、长内容及加载/空/错误/无权限/未知状态。合成样例、真实浏览器和真实渠道结果分开报告。
