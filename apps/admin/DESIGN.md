# Design

状态：管理平台现行设计约束与采用边界，不是页面实现或生产验收。

## Surface

- 产品：洲洲商行管理平台，Web-first，Operate 模式。
- 适用范围：仅管理平台；用户站有独立的 PRODUCT/DESIGN。
- 核心结构：保留现有 AppShell 的侧栏、顶栏、多对象标签与工作区；当前优化集中在子页面交互和 UI，不整体替换管理壳、配色或深浅主题。
- 代表性页面：登录/2FA 引导、桌面 PIN 锁屏、boss 工作台、运营队列与订单履约详情；客服工作台复用同一壳并按权限呈现订单内容。

## Direction

### 视觉命题

稳重的黑灰运营工作面承载高信息密度，多色数据图表提供清晰区分；先锋和游戏行业气质只出现在精确的交互、图表色彩和认证入口，不把工作台做成游戏 HUD。

### 基础层

- 默认使用近黑、深石墨和烟灰层次；侧栏、顶栏、卡片、图表区和表格区通过明度与细边界区分。
- 采用黑灰底色，不使用大面积高饱和背景、玻璃拟态或持续发光边缘。
- 品牌名为洲洲商行；Owner 已提供暂用 Logo，统一从 [品牌物料](../../assets/brand/README.md) 取用，替换中性占位。

### 数据层

- 图表允许使用蓝、青、紫、粉、绿、橙等多色系列，以支持多游戏、多指标、多状态的区分。
- 分析系列色与状态色分开：绿色/红色不同时承担所有图表系列；红色主要表达危险/错误，绿色主要表达成功/正向状态，琥珀色表达待处理/警告。
- 所有关键系列同时提供图例、文字、线型、标记或表格信息；不能只靠颜色区分。
- 图表必须保留单位、时间范围、截至时间、图例和加载/空/未知语义；未知不能显示成 0。
- 色彩沿用 [现有主题](src/styles.css)；明暗主题中保持语义一致并检查对比度，局部优化不引入第二套管理端主题。

## Information Architecture

- 同一管理壳按登录管理员的权限范围改变首页内容、导航入口、字段可见性和可执行动作。
- boss 首页强调整体运营与账目数据；运营首页强调审核、供给和运营队列；客服首页强调当前订单、接待、交付和验收上下文。
- Boss 首页以经营和账目聚合为主，同时突出异常与待办；其他管理员以获授权的处理事项为主。首页采用服务端按有效权限派生的固定编排，不提供自由拖拽；不把所有数据等量堆成 KPI 卡片。
- 列表、总计、下钻和导出必须使用同一服务端口径与数据范围；前端图表映射不承担资金计算。
- 审批路径用 Approvals UI 交互流程图表达，节点可选择并查看真实记录；事件时间线补充审计。候选审批组内任一合格人首个有效批准或拒绝生效，不绘制多人逐级必签，不把批准画成执行或到账。
- 客服工作台优先清楚组织会话队列、聊天和当前对象上下文；接待状态、未读、订单阶段及可用处理分别呈现，窄屏调整分区而不丢失关键任务。
- 列表用于定位和比较，详情用于理解对象、关联事实与下一步；筛选、排序、分页和空结果使用一致交互。历史来源仅在理解或核对所需处说明，已取得的字段按事实展示，不以“旧数据”统一替代内容。
- 订单履约、结算、余额入账与渠道支付/退款状态分开表达；待核对、无权限、未读取、暂无记录与零金额各有明确语义。所有影响订单的写操作通过明确入口并二次确认，按权限、原因及真实结果反馈。

## Component Adoption

| 能力 | 本轮决定 | 边界 |
|---|---|---|
| 管理壳与基础控件 | 保留 PaceUI 管理壳；新增与优化页面优先复用本仓成熟组件，再按需采用 ReUI 与 shadcn/ui 的 Base UI 组件 | 复用现有主题与依赖，保留许可及出处；业务页面使用统一按钮、表单和弹层组件，不裸写原生控件；不整套替换或复制 Pro 资源 |
| 图表 | EvilCharts Recharts 方向为统一来源，统一走本仓 chart wrapper | 只采用已核 MIT 的上游源码；不复制 ECharts 第二引擎，不同时为同一图表安装两套 engine |
| 统计卡/布局 | PaceUI Stats 1–4 等已核 Free 源码 + 本仓共享 dashboard 组件 | 不复制 Pro/整站 Next 工程；不新建第二套 Button/主题 |
| 普通表格 | shadcn 表格优先 | 先验证筛选、排序、分页、列对齐和行操作，不预装聚合表格 |
| 聚合/透视表格 | 1771/LyteNyte 延后 | Core 为 Apache 2.0；PRO 为商业许可。只有真实数据量和决策需求成立后再评估 |
| 审批可视化 | Approvals UI 流程画布与节点 | 基于受权申请事实展示、选择与查看；不复制 quorum/串行策略语义，不建设拖拽策略编辑器 |
| WebGL/shader | 登录/引导局部可选 | 懒加载、不可见时暂停、支持 reduced-motion 和静态降级；不作为全站依赖 |

2026-10-12 Owner 确认后续管理平台开发优先采用 ReUI 与 shadcn/ui。先复用真实页面中效果好的实现，4291 展示候选仅供参考；具体组件按当前业务任务、权限状态、包体与兼容性选择。普通表格继续复用现有 Table，不因组件库有 DataGrid 就新增数据引擎。

组件与许可参考：[ReUI](https://reui.io/docs)、[shadcn/ui](https://ui.shadcn.com/docs/components)、[ReUI 许可](https://reui.io/legal/license)、[Bklit](https://github.com/bklit/bklit-ui)、[EvilCharts](https://github.com/legions-developer/evilcharts)、[LyteNyte](https://www.1771technologies.com/docs/intro-installation)、[Approvals UI](https://github.com/DylanMerigaud/approvals-ui)。采用前仍需按实际版本和依赖清单复核，不把公开示例的存在当成性能或生产验收。

## Representative Validation

按任务选择受影响的代表页面及共用状态验证，不把个别页面通过等同于全站验收：

1. 登录/密码+2FA，以及首次绑定/恢复引导；借鉴 Devl 的分屏构图和一步一决策节奏，不照搬示例账号、文案或工作区业务。
2. 桌面 PIN 锁屏：遮蔽受保护内容；服务端锁态仍是安全边界；连续 5 次 PIN 错误后回到密码+2FA恢复并重设 PIN。
3. boss 工作台：整体运营与账目数据的合成展示，包含多色图表、口径信息、异常入口和可下钻对象。
4. 运营队列与订单履约详情：表格可扫读，配合审核/供给队列、订单时间线、人工履约状态和权限范围。
5. 客服角色状态：复用同一壳，只显示当前订单及获授权字段/动作；不把建群、消息发送或批准直接画成履约完成/到账。

每个代表页至少覆盖：正常、加载骨架、空数据、错误/未知数据、权限范围不同；另验证桌面锁屏与移动窄屏降级。移动端不展示 PIN 锁屏流程。

安全整合说明：窄屏/移动不展示PIN不是解锁条件。已锁会话保持受限，需通过允许的解锁或完整重新认证；改变视口/User-Agent不得恢复读取或操作。工作台角色视角也不替代待确认的Q4对象/字段权限。

## Interaction, Motion, and Accessibility

- 桌面端完成完整工作流；移动端采用结构性降级，优先保留登录、查看、审批、查单和异常确认，复杂表格与配置不强行等价复刻。
- 关键组件保留默认、悬停、焦点、激活、禁用、加载和错误状态；按钮隐藏不等于授权。
- 支持键盘完成登录、筛选、表格行操作、审批查看和锁屏恢复；焦点、错误、返回路径和权限限制清晰可见。
- 工作台避免页面加载编排和无意义循环动画；动效只表达状态、反馈、加载或局部揭示。登录/引导的 shader 不得遮挡表单、刻度、数据或关键操作。
- 深浅主题均需通过对比度与 reduced-motion 检查；状态同时提供文字、图标、线型或图例。

## Open Decisions

- 品牌 Logo 见 [品牌物料](../../assets/brand/README.md)；具体变体按背景和空间适配。沿用当前主题 token，字体、对比度与密度按受影响页面核验。
- 1771 是否有必要、移动端具体断点与表格列优先级，待真实数据范围和代表页验证后确认。
- 经营指标、账目口径、数据覆盖和导出范围仍由对应业务/数据契约确认；视觉文档不替它们定义或宣称已存在。
