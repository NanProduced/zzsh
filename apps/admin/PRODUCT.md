## Platform

web

## Users

- 两位独立、同级最高权限的 boss：查看整体运营与账目数据，并处理获授权的管理动作。
- 运营人员：处理运营数据、审核与供给工作流。
- 客服人员：处理当前订单、接待、交付及订单履约上下文。
- 其他管理员按当前权限范围使用对应工作台；角色名称不直接决定权限。

普通管理员权限为有效角色权限并集，加个人授权，减个人明确禁止；个人禁止优先。页面展示的入口不能替代服务端授权。

## Product Purpose

洲洲商行管理平台是面向游戏领域平台的运营工作台，帮助管理员完成账号安全、审核与供给、订单履约、资金异常处理和审计追溯。

成功标准是：管理员登录后立即看到与自身权限范围匹配的工作内容，能够找到对象、完成获授权的处理、看到结果或下一步，并保留可追溯的业务与审计事实。平台不以堆叠通用指标或视觉冲击替代任务完成。

## Positioning

这是一个按管理员身份和权限范围组织内容的运营工作台，而不是所有角色共享一套泛化大屏。它保留熟悉的 shadcn admin dashboard 壳，但让 boss、运营和客服进入不同的数据重点与处理入口。

## Operating Context

- 桌面端承载完整运营工作流和 UI 细节。
- 移动端提供小屏适配与必要的 UI 降级，优先保证可操作性；移动端不提供管理员 PIN 锁屏。
- 移动端不提供PIN界面不等于绕过服务器锁态；缩小窗口、更改User-Agent或新开标签页不能解锁已有会话。已锁会话在无PIN界面的终端只能完成完整重新认证后继续，不能隐藏遮罩即恢复访问。
- 深色为默认主题，并支持浅色主题切换；两种主题都必须保持数据可读性。
- 代表性验证使用明确标记的合成数据，不暗示真实营收、订单、用户或资金数据。
- 首轮代表场景包括登录/2FA 引导、桌面 PIN 锁屏、boss 工作台、运营队列与订单履约详情；客服工作台复用同一管理壳并呈现不同角色内容。
- 管理员密码、2FA、PIN 锁屏、会话撤销和授权由服务端保障；视觉遮罩不是安全边界。

## Capabilities and Constraints

- 工作台内容按登录管理员的角色、权限、对象范围和字段可见性呈现；同一管理壳不代表所有人看到或能操作相同内容。
- boss/运营/客服是工作台内容视角，不是硬编码权限或已冻结数据范围。Q4的本人/团队/全量订单及字段边界仍待运营确认，设计不能将“当前订单”擅自解释为全量授权。
- 两位 boss 同级，不创建第三个日常 root 或共享凭据。
- 管理员使用密码加 2FA；支持手动锁定与自设闲置时长自动锁定。PIN 为 6 位数字；连续错误 5 次后须以密码加 2FA 恢复并重设 PIN。
- 锁屏作用于当前浏览器会话的全部标签页，其他设备会话独立；刷新、新标签或隐藏按钮不能绕过服务端锁态和授权检查。
- 审批表达候选审批组内首个合格且有效的批准或拒绝生效；不表达多人逐级必签。批准不等于执行，也不等于资金到账。
- 管理平台服务端负责业务规则、对象授权、资金与审计；客户端不决定价格、授权、支付成功或退款到账。
- 黑灰底色承载稳定工作面；图表可使用蓝、青、紫、粉、绿、橙等多色系列区分数据。状态色与分析色分开，数据不能只靠颜色表达。
- 首期不因视觉参考新增业务范围、真实数据接入、全站 WebGL、任意策略编辑器或未经证据支持的聚合表格能力。
- 管理 API、身份、幂等和错误契约不依赖 Web DOM、Cookie、Server Actions；未来 iOS、Android 和微信小程序仍经服务端 BFF 适配。

## Brand Commitments

- 管理平台与未来用户站共享品牌名和 Logo 资产；当前 Logo、品牌名细节及相关资产尚未确认，设计使用中性占位，不伪造品牌标识。
- 管理端允许先锋、科技感和游戏行业气质，但数据可读性、操作效率、可访问性和长时间工作舒适度优先。
- 登录与首次引导可使用局部科幻/WebGL 氛围；业务工作台不全站滥用，必须有静态、低性能和 reduced-motion 降级。

## Evidence on Hand

- 当前工程基线：`apps/admin` 为 React/Vite/TypeScript 管理站，使用 Tailwind CSS；shadcn/ui 按实际组件需求采用。
- 业务与安全边界依据当前仓库的技术决策、M2 简报、M2 准入评估和管理平台数据分析研究，并经本设计会话 Owner 确认。
- 公开视觉参考包括 Devl auth/onboarding、No Code-Shader、Bklit、EvilCharts、1771、Approvals UI 与 Pace UI dashboard；它们只提供构图、组件能力或配色参考，不构成业务事实或整套依赖采购决定。
- 当前没有已确认的 Logo、品牌色、真实经营数据或可用于原型的生产页面素材。

## Product Principles

1. 先呈现当前管理员真正能处理的事，再呈现指标。
2. 发现问题、找到对象、安全处理、验证结果必须形成连续路径。
3. 数据事实、渠道事实、审批事实、执行事实和到账事实不能在界面上混成一个成功状态。
4. 服务端授权和审计是真实边界；前端隐藏、锁屏遮罩和旧页面状态都不是授权。
5. 视觉表达可以有游戏行业个性，但不能增加阅读、判断或操作成本。

## Accessibility & Inclusion

- 关键流程支持键盘操作、可见焦点、清晰错误与返回路径。
- 深浅主题均需保持足够对比度；状态同时使用文字、图标、线型或图例，不能只依赖颜色。
- 代表页必须覆盖正常、加载、空数据、错误/未知数据、权限范围不同、桌面锁屏和移动窄屏降级状态。
- 动画尊重 reduced-motion；不支持 WebGL 或低性能设备仍可完成登录和工作台操作。
